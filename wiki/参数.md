# 参数与 API 参考

本页是 eInkViews 的接口与参数权威参考。所有参数名、枚举取值、默认值、状态码、响应头均以仓库代码为准，逐项可从下列源文件核对：

- `config.py`（全局默认值）
- `modules/register/auto_view_routes.py`、`auto_json_routes.py`、`auto_page_routes.py`、`random_view_route.py`、`template_routes.py`（路由形态）
- `modules/prerender/params.py`（`size` / `rotate` / `invert` / `cmode` / `format` 的解析与降级）
- `modules/generate_views/canvas_factory.py`（`SIZES`、`PALETTES`）、`image_output.py`（格式注册表与黑名单）、`image_transform.py`、`palette_mapper.py`
- `modules/auth/auth.py`（鉴权）、`modules/errors/errors.py`（错误码）、`modules/utils/rate_limiter.py`（限流头与 429 文案）

本地默认访问地址为 `http://127.0.0.1:5000`（`PORT` 环境变量可覆盖，见 `modules/run_core.py`）。下文示例统一使用该完整 URL，且**一律不含 `palette` 参数**（本项目没有该参数，详见第 3 节）。

## 1. 路由形态

### 1.1 通用入口（由框架自动注册，非插件手动书写）

| 入口 | 方法 | 路径模板 | 说明 |
| :--- | :--- | :--- | :--- |
| 视图路由 | GET | `/{plugin_name}/view/{kind}` | 渲染并返回图像；`{kind}` 为插件 `view/` 下的子目录名 |
| JSON 路由 | GET | `/{plugin_name}/json/{name}` | 返回 JSON；`{name}` 为插件 `json_module/` 下的模块名 |
| 页面路由 | GET | `/{plugin_name}/page/{name}` | 返回静态 HTML；`{name}` 为插件 `page/` 下的文件名（去 `.html`） |
| 随机视图 | GET | `/random/views` | 按权重从候选视图中随机选一个渲染 |
| 首页 | GET | `/` | 返回 `public/pages/index.html`；dev/prod 下按锚点改写本地专属块 |
| 存活探针 | GET | `/healthz` | 仅本地链路注册（dev/prod），Vercel 侧没有；不查库、不渲染、不写日志、不占限流额度 |
| 站点图标 | GET | `/favicon.ico` | 返回 `public/favicon.ico` |
| 静态资源 | GET | `/public/**` | `public/` 目录静态挂载 |

当前仓库随附的示例插件名是 `plugin_template`，其视图种类为 `summary`、`detail`（各含 `hxl` / `h2xl` 两个尺寸），JSON 模块为 `demojson`。示例 URL 均以它为准。

```bash
# 视图：summary 视图，横屏 384x184
curl "http://127.0.0.1:5000/plugin_template/view/summary?size=hxl"

# 视图：detail 视图，横屏 400x300，透传业务参数 a / b
curl "http://127.0.0.1:5000/plugin_template/view/detail?size=h2xl&a=alpha&b=beta"

# JSON
curl "http://127.0.0.1:5000/plugin_template/json/demojson"

# 随机视图：候选为 plugin_template.summary 的 hxl（权重 1.0）
curl "http://127.0.0.1:5000/random/views?routes=plugin_template.summary:hxl"

# 存活探针
curl "http://127.0.0.1:5000/healthz"
```

> 页面路由已按插件 `page/` 目录自动注册，但 `plugin_template` 目前没有 HTML 页面文件，故无可用示例；URL 形如 `http://127.0.0.1:5000/plugin_template/page/<页名>`。

| 备份下载 / 恢复 | GET / POST | `/admin/api/backup/download`、`/admin/api/backup/restore` | 下载整库一致性快照（SQLite 在线备份）/ 上传整库替换（先校验再自动备份当前库，成功后重建内存态并使登录态失效） |
| 配置导出 | GET | `/admin/api/config/export` | 导出配置包（JSON），含已覆盖的全局配置项、插件配置项覆盖与各用户组的限额 / 配额字段；数据库不可用返回 400 |
| 配置导入 | POST | `/admin/api/config/import` | 导入配置包（结构与导出包相同），经结构校验与白名单过滤后批量写回并热生效；数据库不可用返回 400 |
| 指标出口 | GET | `/metrics` | 不属于管理面板，与 `/healthz` 同属本地链路的免鉴权端点：Prometheus 文本格式，不占限流额度、不写请求日志；`METRICS_TOKEN` 非空时需 `?token=` 或 `Authorization: Bearer`，否则 403 |

其余管理接口按领域挂在 `/admin/api/` 前缀下（插件、配置、用户、日志、预渲染等）。`/admin` 前缀在鉴权白名单里，表示**不校验 evkey**，但不代表免授权——本地模式下 `/admin/api/**` 由 `app_core._check_admin_api_access()` 额外把关，必须是已登录的**管理组**用户且开放了对应后台分页；仅 `/admin/api/auth/*` 与 `/admin/api/my/*` 豁免（这两者各自在路由内校验身份）。

所有请求都会带上/透传 `X-Request-ID`（请求头已有则复用，响应头回写），报错时控制台会先打一行 `[req=<id>] METHOD PATH STATUS <ms>`，排查时以它对齐堆栈与具体请求。

**配置包的导出 / 导入**（`GET /admin/api/config/export`、`POST /admin/api/config/import`）：

- 导出包结构：`{schema: 'einkviews-config', version: 1, framework_version, exported_at, config: {...}, plugins: {...}, groups: [...]}`。其中 `config` = 已覆盖的全局配置项；`plugins` = 插件配置项覆盖；`groups` = 各用户组的限额 / 配额字段。
- 用途边界：可读、可 diff、可跨实例搬配置；整库回滚请用备份 / 恢复。
- 导入请求体与导出包同结构；`schema` 必须为 `einkviews-config`，`version` 不得高于当前支持版本，否则 400。
- 导入处理顺序：结构校验 → 白名单过滤（只接受本系统已登记的全局配置项；插件配置只接受当前加载成功且该插件声明过的键）→ 批量写回 → 热生效 → 记审计日志。
- 导入响应体：`{success, message, result}`，其中 `result` 按 `config` / `plugins` / `groups` 分组给出 `applied`（已导入）/ `skipped`（不认识或已不存在）/ `rejected`（取值非法）。不认识的键与取值非法的项分别落到 `skipped` / `rejected`，**不会整包失败**。
- 两个接口在数据库不可用时均返回 400。

## 2. 鉴权参数

### 2.1 evkey 的位置

`evkey` 可放在**请求头**或**查询参数**中，读取顺序为「请求头优先，查询参数兜底」：

```text
请求头:  evkey: <你的密钥>
查询参数: ?evkey=<你的密钥>
```

鉴权由 `modules/auth/auth.py` 的 `check_auth()` 在 HTTP 中间件中执行，流程顺序为：

1. **Session Cookie**：若带 `ink_session` Cookie（管理面板登录态），校验通过后即放行；
2. **dev 模式**：`config.AUTH_ENABLE` 为 `False` 时注入默认 dev 用户（`id=1` / `admin` 组），跳过鉴权；
3. **白名单**：命中 `AUTH_WHITELIST` 的路径免鉴权；
4. **evkey 两级校验**：
   - **第一级（数据库账号）**：数据库可用且 `accounts` 表中已有账号时，按 evkey 匹配该账号下的 evkey（JOIN `evkeys`），取账号所属用户组；匹配不到直接 401。
   - **第二级（环境变量回退）**：数据库无账号（或 Vercel 模式不可用数据库）时，回退把请求的 evkey 与环境变量 `EVKEY` 做定长比较。

### 2.2 免鉴权白名单

`config.AUTH_WHITELIST` 的取值如下，匹配规则为：`'/'` **只做精确匹配**，其余按**前缀匹配**：

| 白名单项 | 匹配方式 |
| :--- | :--- |
| `/` | 精确匹配（仅首页，不匹配子路径） |
| `/healthz` | 前缀匹配 |
| `/metrics` | 前缀匹配 |
| `/public` | 前缀匹配 |
| `/favicon.ico` | 前缀匹配 |
| `/admin` | 前缀匹配（放行全部管理路径、`/admin/api/**`，注册页 `/admin/register` 也已落在该前缀内） |

### 2.3 鉴权失败的响应

统一走 `error_response()`，状态码 `401`，响应体 `{success:false, message, code}`。可能的 `message`（逐字来自代码）：

| message | 触发条件 |
| :--- | :--- |
| `缺少鉴权密钥 evkey` | 需鉴权路径未携带 evkey |
| `无效的 evkey，用户不存在或已禁用` | 数据库有账号但 evkey 匹配不到 |
| `未配置鉴权密钥 (EVKEY 环境变量或数据库用户)` | 数据库无账号且未配置 `EVKEY` 环境变量（fail-closed） |
| `鉴权失败，evkey无效` | 与环境变量 `EVKEY` 比较不一致 |
| `请先登录管理面板` | 非 admin 或未登录访问 `/admin/api/**`（401） |
| `需要管理员权限` | 已登录但非管理组（或该管理组未开放对应后台分页）访问 `/admin/api/**`（403） |

```json
{
  "success": false,
  "message": "缺少鉴权密钥 evkey",
  "code": 401
}
```

> Vercel 模式未配置 `EVKEY` 时，所有需鉴权请求一律 401（fail-closed）。

## 3. 通用图像参数

视图路由的保留参数为 `size` / `rotate` / `invert` / `cmode` / `format`（定义于 `modules/prerender/params.py` 的 `_RESERVED`），它们由路由层解析、**不透传**给 `generate_image`；其余查询参数一律透传为业务参数。

| 参数名 | 类型 | 默认值 | 合法取值 | 说明 | 示例 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `size` | string | 无（缺失报 400） | 见 3.1 尺寸表全部键名 | **必需**。缺失时 `ParamError('缺少 size 参数')`；形状不是模块名（`hxl.py` / `../hxl` / `_hxl`）报 400 `size 参数不合法`；形状合法但视图模块不存在则报 400 `视图 <plugin>.view.<kind>.<size> 不存在` | `?size=hxl` |
| `rotate` | string | 插件 `DEFAULT_ROTATE`，无则 `config.DEFAULT_ROTATE`（`0`） | `c`=270°、`cc`=90°、`h`=180°；**其它值报 400** `rotate 参数必须为 c / cc / h` | 逆时针旋转并 `expand`（画布随旋转扩展） | `?rotate=h` |
| `invert` | string | 插件 `DEFAULT_INVERT`，无则 `config.DEFAULT_INVERT`（`False`） | `t`=反色、`f`=不反色 | 仅接受 `t` / `f`，其它值报 400 `invert 参数必须为 t 或 f` | `?invert=t` |
| `cmode` | string | 插件 `DEFAULT_ARGS` 的 `cmode`，无则 `config.DEFAULT_CMODE`（`None`） | `2bw`、`r2y`、`y2r`、`yr2r`、`yr2y`；`None` 或 `None` 字符串=不映射；**其它值报 400** `cmode 参数必须为 None / 2bw / r2y / y2r / yr2r / yr2y` | 对调色板表做精确重映射（见 3.2） | `?cmode=2bw` |
| `format` | string | `config.DEFAULT_IMAGE_FORMAT`（`jpg`） | `jpg`、`jpeg`、`png`、`bmp`、`webp`、`tiff`、`gif`、数组格式族 `array`/`bwarray`/`bwrarray`/`bwyarray`/`bwryarray`/`7carray`（见 3.3 黑名单） | 输出格式，统一 `lower()` 处理；不受黑名单/权限限制时按注册表输出 | `?format=bwrarray` |
| `evkey` | string | 无 | 任意密钥字符串 | 鉴权密钥（请求头或查询参数，见第 2 节） | `?evkey=xxx` |
| 其它参数 | string | 插件 `DEFAULT_ARGS` 中同名项 | 由插件自定义 | 透传给 `generate_image(**params)`；未在 `DEFAULT_ARGS` 中且未传则视图需自行兜底 | `?a=alpha&b=beta` |
| `palette` | - | - | - | **不存在此参数**。调色板不是 URL 参数，由视图内部调用 `create_canvas(size_key, palette_type, cmode)` 时指定 | - |

> `format` 在随机视图端点同样受支持；`size` 在随机视图端点**不是**独立参数，尺寸写在 `routes` 中。

> **非法值一律 400，不再静默回落。** URL 上显式传的 `rotate` / `invert` / `cmode`（随机视图端点的全局查询参数与 `routes=` 内同名参数都算）取值不在上表范围内时直接报错。`size` 则必须是合法模块名（`hxl.py`、`../hxl`、`_hxl` 一类直接 400）。这样设备固件把参数拼错时会立刻拿到 400，而不是收到一张「参数没生效」的正常图。插件的 `DEFAULT_ROTATE` / `DEFAULT_INVERT` / `DEFAULT_CMODE` 属配置错误，只在配置层体现，不影响请求期校验。

### 3.2 调色板映射 `cmode`（`palette_mapper.map_palette`）

调色板本身由视图在创建画布时指定（`PALETTES` 键：`bw`、`bwr`、`bwy`、`bwry`、`7color`），URL 层只能通过 `cmode` 对其做重映射：

| `cmode` | 效果 |
| :--- | :--- |
| 缺省 / `None` | 不映射，返回原调色板 |
| `2bw` | 白保持白，其余一律映射为黑（二值化） |
| `r2y` | 红色映射为黄色 |
| `y2r` | 黄色映射为红色 |
| `yr2r` | 红/黄均映射为红色 |
| `yr2y` | 红/黄均映射为黄色 |
| 其它值 | 报 400 `cmode 参数必须为 None / 2bw / r2y / y2r / yr2r / yr2y`（`map_palette` 自身对未识别值仍保持调色板不变，但 URL 层不会再放它进来） |

### 3.3 输出格式（`image_output._FORMAT_REGISTRY` + 数组格式族）

| `format` | Pillow 格式 | MIME | 扩展名 |
| :--- | :--- | :--- | :--- |
| `jpg` | JPEG | `image/jpeg` | `.jpg` |
| `jpeg` | JPEG | `image/jpeg` | `.jpg` |
| `png` | PNG | `image/png` | `.png` |
| `bmp` | BMP | `image/bmp` | `.bmp` |
| `webp` | WEBP | `image/webp` | `.webp` |
| `tiff` | TIFF | `image/tiff` | `.tiff` |
| `gif` | GIF | `image/gif` | `.gif` |
| 数组格式族（见下表） | 原始位流 | `application/octet-stream` | `.bin` |

编码参数（每次现从 `config` 取，面板改完即时生效）：

| 格式 | 参数 | 默认值 |
| :--- | :--- | :--- |
| jpg / jpeg | `quality` / `subsampling` / `progressive` | `100` / `0` / `False` |

| png | `compress_level` | `6` |
| tiff | `compression` | `tiff_lzw` |

#### 数组格式族（`modules/generate_views/array_formats.py`）

按面板调色板的色数打包的紧凑位流，直接给三色/四色/七色屏用，不再被亮度阈值压成黑白。

| `format` | 调色板来源 | 码表（0..n-1） | 每像素位数 | 字节长度 |
| :--- | :--- | :--- | :--- | :--- |
| `array` / `bwarray` | `PALETTES['bw']` | 白, 黑 | 1 | `ceil(w*1/8)*h` |
| `bwrarray` | `PALETTES['bwr']` | 白, 黑, 红 | 2 | `ceil(w*2/8)*h` |
| `bwyarray` | `PALETTES['bwy']` | 白, 黑, 黄 | 2 | `ceil(w*2/8)*h` |
| `bwryarray` | `PALETTES['bwry']` | 白, 黑, 红, 黄 | 2 | `ceil(w*2/8)*h` |
| `7carray` | `PALETTES['7color']` | 白, 黑, 红, 黄, 绿, 蓝, 橙 | 3 | `ceil(w*3/8)*h` |

- 颜色序即码值，直接取自 `canvas_factory.PALETTES`（白=0、黑=1、红=2、黄=3、绿=4、蓝=5、橙=6）。
- 位序 **MSB 在前**，每行末尾补 0 bit 到整字节（与 PIL 模式 `1` 的 `tobytes()` 同一约定）。补位的 0 解码为白。
- 编码器不产出空档码（2bpp 的 3、3bpp 的 7）。
- 颜色降级**只走 `cmode` 规则**（`r2y` → `y2r` → `yr2r` → `yr2y` → `2bw`，`2bw` 兜底）：目标调色板里没有的颜色按顺序试，仍不命中才压成白/黑，不做最近色量化。所以 `bwyarray` 上的红像素会先被 `r2y` 变成黄（码 2），而不是直接掉成黑。
- `bwarray` 是 `array` 的等价别名，两者逐字节相同；黑名单与用户组权限键统一按 `array` 查（用别名绕不开）。
- `cmode` 不在这里参与运算：它已在渲染链路改过调色板，数组打包只做「颜色 → 码」的搭桥。
- ⚠️ **破坏性变更**：`array` 的码表已从旧的「白=1 / 黑=0」（PIL 亮度阈值）改为索引码「白=0 / 黑=1」。存量固件若仍按旧约定解析，黑白会全反。

**默认黑名单 `IMAGE_FORMAT_BLACKLIST`**：`['webp', 'tiff', 'gif', 'bmp', 'png']`。命中黑名单的格式报 400 `XXX 格式已被框架层面禁止生成`。因此**默认配置下可用的输出格式只有 `jpg` / `jpeg` 与整个数组格式族**；其余格式需在管理面板移除黑名单项后才可用。两边都不认的值报 400 `不支持的输出格式: xxx，支持 7carray, array, bmp, bwarray, bwryarray, bwrarray, bwyarray, gif, jpg, png, tiff, webp`。

## 4. 按业务分类的必需参数规则

参数优先级（**从高到低**）：**URL 显式查询参数 > 插件 `plugin_config.py` 的 `DEFAULT_ARGS` > 全局 `config.py` 默认值**。实现上先把 `DEFAULT_ARGS` 铺底，再用查询参数覆盖；`rotate` / `invert` / `format` 无 URL 参数时依次回退到插件 `DEFAULT_ROTATE` / `DEFAULT_INVERT` 与 `config.DEFAULT_ROTATE` / `DEFAULT_INVERT` / `DEFAULT_IMAGE_FORMAT`。

| 参数类别 | 必需参数 | 校验要求 | 校验所在层 |
| :--- | :--- | :--- | :--- |
| 地理位置类 | `lat`、`lon`、`tz` | 任一出现则三者都要齐（项目约定） | **框架不校验**；`tz` 由视图函数显式接收并透传，`lat` / `lon` 目前无插件使用，仅作业务参数透传 |
| 用户标识类 | `username` | 非空 | `modules/admin/auth_routes.py`（登录/注册接口 `body.get('username','').strip()`，为空返回 400 `请输入用户名`）；**视图 / JSON 路由不做此校验** |
| 内容选择类 | 无 | 直接透传给插件数据获取 | 插件层 |
| 资源文件类 | `json_name`（JSON 模块名） | 名字必须对应已存在的 `json_module/*.py` | 它是**路径段** `/{plugin}/json/{name}`，非查询参数；不存在的名字不会命中路由（FastAPI 默认 404），模块导入失败或未实现 `to_json` 报 **400** `JSON模块 ... 不存在` |
| 纯内容类 | 无 | 不做额外参数校验 | - |

资源文件类的另一种情形是插件内文件：`get_plugin_default_args()` 对非字典的 `DEFAULT_ARGS` 一律当空字典处理，避免下游 `dict()` 直接抛错。

## 5. 响应

### 5.1 成功响应

| 端点 | `Content-Type` | 其它响应头 |
| :--- | :--- | :--- |
| 视图 / 随机视图（图像） | 见 3.3 表格（如 `image/jpeg`） | `Content-Disposition: inline; filename=<plugin>_<kind>_<size>.<ext>` |
| 数组格式族（`format=array` / `bwrarray` 等） | `application/octet-stream` | `Content-Disposition: inline; filename=<plugin>_<kind>_<size>.bin`；`X-Raw-Bytes: <字节数>` |
| JSON 路由 | `application/json; charset=utf-8` | - |
| 页面路由 | `text/html`（`FileResponse`） | 本地模式下 HTML 额外带 `X-Frame-Options: DENY`、`X-Content-Type-Options: nosniff`、`Referrer-Policy: same-origin` |
| `/healthz` | `application/json` | 返回 `{"success":true,"status":"ok","mode":<模式>,"version":<版本>}` |

**缓存相关响应头**：

- 本地 `dev` / `prod` 的图像响应**不带** `Cache-Control` / `ETag` 等缓存头。
- 仅 `vercel` 模式在 `config.EDGE_CACHE_TTL > 0` 时下发 `Vercel-CDN-Cache-Control: public, max-age=<ttl>`。该头由 Vercel 独占、**不会返回给客户端**，因此 ESP32 / 浏览器看不到，不会触发设备端缓存。
- 图片响应统一用 `Response(content=bytes)` 整体返回，**不使用** `StreamingResponse`。

### 5.2 预渲染命中表现

命中定时预渲染成品缓存时：响应体字节**与实时渲染完全一致**（同样的 `Content-Type` 与 `Content-Disposition`），**不额外增加任何标识响应头**。命中路径仍会重跑格式黑名单与用户组格式权限校验；差异只体现在服务端：`request.state.prerender_hit = True`（请求日志的 `cache_hit` 记为命中），并计入命中统计。`rotate` / `invert` / `cmode` / `format` 不进缓存键，命中时按当次请求现场套用。

### 5.3 限流（429）

限流由 `modules/utils/rate_limiter.py` 的 `rate_limit_middleware` 执行，**仅本地 dev / prod 生效**（Vercel 无此中间件）。限流白名单 `RATE_LIMIT_WHITELIST`：`/healthz`、`/metrics`、`/public`、`/favicon.ico`、`/admin`。

触发限流时返回 `error_response(message, 429)`，即：

```json
{
  "success": false,
  "message": "请求过于频繁，每分钟限制 30 次，请稍后再试",
  "code": 429
}
```

429 文案取值：

| 触发窗口 | message 模板 |
| :--- | :--- |
| 每分钟速率 | `请求过于频繁，每分钟限制 {limit} 次，请稍后再试` |
| 无组身份·每小时 | `请求过于频繁，每小时限制 {limit} 次，请稍后再试` |
| 配额 `trial` | `总量额度已用完（共 {limit} 次），如需继续请联系管理员` |
| 配额 `day` | `今日请求已达上限（{limit} 次），请明天再试` |
| 配额 `week` | `本周请求已达上限（{limit} 次），请下周再试` |
| 配额 `month` | `本月请求已达上限（{limit} 次），请下月再试` |
| 配额 `year` | `本年请求已达上限（{limit} 次），请明年再试` |

**成功响应**携带的限流余量头（仅当对应限额 `> 0` 时才设置）：

| 响应头 | 含义 |
| :--- | :--- |
| `X-RateLimit-Limit` | 每分钟速率上限 |
| `X-RateLimit-Remaining` | 每分钟剩余次数 |
| `X-RateLimit-Long-Limit` | 长周期额度上限（配额实际额度或全局每小时上限） |
| `X-RateLimit-Long-Remaining` | 长周期剩余次数 |

> 429 响应是提前返回的，**不携带**上述 `X-RateLimit-*` 头。

## 6. 错误码总表

所有错误（异常处理器、中间件、管理 API）统一由 `modules/errors/errors.py` 的 `error_response()` 构造：

```json
{
  "success": false,
  "message": "错误描述文本",
  "code": 400
}
```

其中 `code` 默认等于 HTTP 状态码（`error_response` 的 `code=None` 时取 `status_code`）。

| 异常 / 场景 | HTTP 状态码 | `message` 表现 |
| :--- | :--- | :--- |
| `NotFoundError` | 404 | 异常消息原文 |
| `ParamError` | 400 | 异常消息原文（并打印栈） |
| `AuthError` | 401 | 异常消息原文 |
| `AccessDeniedError` | 403 | 异常消息原文 |
| `RequestValidationError` | 422 | 固定 `请求参数校验失败` |
| `HTTPException`（FastAPI 内置） | 取异常自带 `status_code` | 异常 `detail` 原文 |
| 其它 `Exception` | 500 | **dev**：`<异常类型名>: <消息>`；**prod / vercel / 其它**：固定 `服务器内部错误`（并打印栈） |

常见 400（`ParamError`）消息：`缺少 size 参数`、`size 参数不合法`、`rotate 参数必须为 c / cc / h`、`invert 参数必须为 t 或 f`、`cmode 参数必须为 None / 2bw / r2y / y2r / yr2r / yr2y`、`视图 <plugin>.view.<kind>.<size> 不存在`、`图片生成失败: ...`、`随机图片生成失败: ...`、`缺少 routes 参数`、`所有权重均为0或未设置，无法选择视图`、`没有可用的视图：候选插件/路由已被禁用，或当前用户组无权访问`、`用户组禁止使用 rotate/invert/cmode 参数`、`XXX 格式已被框架层面禁止生成`、`不支持的输出格式: xxx，支持 ... / array`。

常见 503（中间件提前返回，非异常）：`插件 <name> 已禁用`、`路由 <path> 已禁用`、`权限校验失败，已拒绝访问`。

> 说明：JSON 路由是**按目录扫描生成**的（`auto_json_routes.py` 遍历 `json_module/` 下的 `.py` 文件），因此「请求一个不存在的 `json_name`」根本不会匹配到任何路由，由 FastAPI 对未知路径返回 404，框架不会为此抛 `NotFoundError`。`NotFoundError` 类与处理器已在 `errors.py` 定义并注册，但**框架自身目前不抛它**，它是留给插件在业务里表达「资源不存在」用的（插件抛出即得 404 JSON）。

## 7. JSON 路由 / 页面路由与视图路由的参数差异

| 维度 | 视图路由 `/view/` | JSON 路由 `/json/` | 页面路由 `/page/` |
| :--- | :--- | :--- | :--- |
| 参数解析函数 | `resolve_view_params()` | `resolve_json_params()` | 无（直接回文件） |
| 保留参数过滤 | 有：`size`/`rotate`/`invert`/`cmode`/`format` 被剔除，不传给 `generate_image` | 无：**全部查询参数原样透传**给 `to_json()` | 无 |
| 插件默认值合并 | 合并 `DEFAULT_ARGS`，查询参数覆盖 | 合并 `DEFAULT_ARGS`，查询参数覆盖 | 无 |
| 必需参数 | `size` 必需 | 无强制必需（由 `to_json` 自行处理） | 无 |
| 响应 | 图像字节 | `JSONResponse`（`application/json; charset=utf-8`） | `FileResponse`（HTML 文件） |
| 预渲染 | 支持，命中按当次 `rotate`/`invert`/`cmode`/`format` 现算 | 支持，JSON 成品整体命中 | 不支持 |
| 失败表现 | 模块/视图不存在 → 400 | 模块不存在或未实现 `to_json` → 400 `JSON模块 ... 不存在` / `... 未实现 to_json` | 文件由路由注册期扫描，不存在即无该路由 |

`json_name` 的定位：它是路径段 `/{plugin}/json/{name}`，由 `auto_json_routes.py` 在注册期扫描 `json_module/` 目录下 `.py` 文件名生成，**不是**查询参数。同理 `page` 的 `{name}` 来自 `page/` 下 `.html` 文件名。

```bash
# JSON 路由：全部查询参数透传给 to_json
curl "http://127.0.0.1:5000/plugin_template/json/demojson?a=alpha&b=beta"

# 视图路由：a / b 是业务参数，size 是保留参数
curl "http://127.0.0.1:5000/plugin_template/view/summary?size=hxl&a=alpha&b=beta"
```
