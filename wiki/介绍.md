# eInkViews 介绍

eInkViews 是一个面向 **Open ePaper Link** 墨水屏的**图像渲染与分发服务**：数据在插件里，设备端只需要拿到一张刚好适配自己屏幕的图。它基于 FastAPI（全异步）、插件化架构，用 Pillow 做像素级排版，把「取数据 → 排版 → 按尺寸/调色板/格式输出 → 分发」这一整条链路收敛成一个可自托管、也可部署到 Vercel 的服务。

## 这是什么

- 墨水屏设备（ESP32 等）固件通常只会「拉一张图然后整屏刷新」。它不关心这张图是天气、日程还是股票，也不想在设备端跑数据抓取和排版逻辑——那既费电又难更新。eInkViews 把这件事挪到服务端：设备只发一个 HTTP GET，拿到可直接显示的图片字节。
- 一个服务要同时面对很多互不相同的硬件：屏幕尺寸从 200×200 到 800×480 不等，横竖屏方向不同，有的两色、有的三色/四色/七色。eInkViews 把这些差异抽象成 `size`（尺寸键）与 `palette`（调色板）两个维度，并在渲染完成后按请求参数施加旋转、反色与调色板映射，让同一份业务内容能服务所有规格。
- 业务内容本身是易变的、来源各异的（第三方 API、本地 JSON、数据库）。项目用**插件**承载业务：每个插件自带数据抓取（`lib/`）与排版（`view/<种类>/<尺寸>.py`），框架只负责路由装配、参数解析、画布创建、并发控制、输出编码与错误处理。新增一类图不需要改框架，改完插件代码还能热重载，不必重启。
- 由于渲染是 CPU 密集且设备会周期性轮询，服务端必须控制成本：字体用 LRU 缓存（不过期）、渲染用按账号的信号量限并发、限流与配额防止单个调用方打满、定时预渲染把「实时渲染」预热成「直接发文件」。这些都在单进程模型下保证一致。
- 最后是「可运维」：本地完整版内置管理面板 `/admin`，把插件开关、用户组权限、账号与 evkey、请求日志、缓存、统计、全局配置、定时预渲染集中到一个 Vercel 风格界面；配置改动热生效，写操作进审计日志，存活探针 `/healthz` 供外部监控轮询。Vercel 版本则刻意裁剪成一个无状态、无持久化的精简函数入口。

## 核心能力

### 插件化与热重载

插件放在 `plugins/<名字>/`，只要目录下有 `routes.py` 就会被自动发现、自动注册，无需登记表。`routes.py` 只做路由装配：调用 `register_view_routes` / `register_json_routes` / `register_page_routes` 扫描 `view/`、`json_module/`、`page/` 下的文件，自动生成 `/{插件}/view/{种类}`、`/{插件}/json/{名字}`、`/{插件}/page/{名字}` 路由。管理面板插件页的「热重载」会重新扫描目录、按对象身份摘除旧路由、清空 `plugins.*` 的模块缓存再重新注册——改插件代码、新增或删除插件目录都不必重启服务。加载失败的插件会把失败原因回传给面板，而不是只报「少了一个」。

插件可在目录下放一份 `plugin.json` 声明元信息（`name` 必须与目录名一致，另有版本、描述、作者、最低框架版本与依赖等可选字段），它是插件元信息的唯一来源，示例见 `plugins/plugin_template/plugin.json`。加载时按依赖顺序排序（被依赖的先加载）：要求的框架版本高于当前版本、依赖的插件不存在或未加载、存在循环依赖时，该插件会被跳过并在面板插件页显示原因；没有清单的插件照旧加载，只标记「未声明清单」；清单存在但格式非法、或 `name` 与目录名不一致则加载失败并显示原因。面板插件页新增「版本」列，启动摘要会报告「其中未声明清单 M 个」。

### 多尺寸、多色与降级

画布尺寸与调色板集中在 `modules/generate_views/canvas_factory.py` 的 `SIZES` / `PALETTES` 字典。尺寸键覆盖横竖屏常见规格（`m` 200×200、`hl` 250×122、`hxl` 384×184、`h2xl` 400×300、`h3xl` 600×480、`h4xl` 800×480，以及对应的 `vl/vxl/v2xl/v3xl/v4xl`）；调色板有 `bw`（白黑）、`bwr`（白黑红）、`bwy`（白黑黄）、`bwry`（白黑红黄）、`7color`（七色）。视图按尺寸键独立实现，规格不在字典里或调色板未知都会抛出明确错误，而不是悄悄画错。

### 旋转、反色与调色板映射

输出前对整图做后处理：`rotate` 走 `image_transform.rotate_image`（`expand=True` 带扩张），`invert` 走 `invert_image`（逐通道 255 取补），`cmode` 走 `palette_mapper.map_palette`。`cmode` 支持 `2bw`（非白即黑）、`r2y` / `y2r`（红黄互换）、`yr2r` / `yr2y`（红黄合并成一种）。因为视图是在 `P` 模式画布上按**索引**绘制、`cmode` 只改**调色板表**不动索引，所以映射可以精确且与「渲染时映射」等价。

### 缓存：字体进 LRU，图片不进池

`modules/cache/cache.py` 只缓存**字体文件**（key 为 `font:{路径}:{字号}`），使用不过期的 `LRUCache`（容量 `CACHE_MAXSIZE`，默认 64）。字体文件运行期不变、FreeType 解析成本高，而 TTL 反而有害——设备每 5~15 分钟轮询一次正好踩在过期边界，会反复重新解析。图片**不进缓存**：`get_image()` 只做实时解码并转 RGBA，`get_indexed_image()` 保留 `P` 模式索引语义供 sprite 逐像素判断。HTTP 响应也不缓存，因为图像是实时生成的；管理面板缓存页可查看命中/未命中/命中率并清空。

### 两级鉴权：数据库 evkey 与环境变量 EVKEY

启用鉴权后按顺序校验：先看会话 Cookie（管理面板登录态），再按白名单放行，然后比对请求头/查询参数里的 `evkey`——**数据库账号下的 evkey 优先**，库里没有匹配再回退到**环境变量 `EVKEY`**。Vercel 模式跳过数据库这一级，直接比对 `EVKEY`，未配置时 fail-closed（全部 401）。`evkey` 的比对用 `hmac.compare_digest` 定长比较，避免逐字节泄露密钥前缀；白名单里 `'/'` 只做精确匹配（若按前缀匹配会放行所有路径）。

### 管理面板 `/admin`

仅本地 dev/prod 模式启用。面板是 Vercel/Geist 风格的单页应用，标签页为「概览 / 插件 / 用户 / 测试 / 日志 / 缓存 / 定时 / 统计 / 配置 / 备份 / 我的」。它能做插件热开关、路由级开关、用户组与账号 CRUD、用户组权限配置（插件/路由/参数粒度）、缓存统计与清除、请求日志与审计查看、统计图表、全局配置实时修改、定时预渲染任务管理、整库备份与恢复。非 admin 用户登录后进入个人控制台，查看自己的额度与额度记录、插件/路由权限并管理 API Key。面板还支持**界面语言**切换（「配置 → 管理面板 → 界面语言」，`auto` / `zh-CN` / `en` 三档，`auto` 为默认并跟随浏览器语言），改完即生效、无需重启；已全量迁移：面板与用户控制台的全部文案、登录 / 注册 / 找回密码 / 首次改密页，以及接口返回的提示信息都随之切换。

### 用户组限额与配额

每个用户组可设 `rate_limit_per_minute`（每分钟速率）、`quota_limit` + `quota_period`（请求配额）与 `max_concurrent_renders`（并发），**均 0 = 不限**。计数范围是**账号**：同一账号下所有 evkey 共用一份额度，不同账号互不影响；有组身份时组限额取代全局 `RATE_LIMIT_PER_MINUTE` / `RATE_LIMIT_PER_HOUR`，全局值仅作无组身份（如环境变量 evkey 鉴权）时的兜底。配额的 `quota_period` 有 `day` / `week` / `month` / `year` / `trial` 五种：前四种按配置时区的自然周期到期**惰性重置**（下次请求发现周期起点变了就当场归零，未用不结转、额度不累加），`trial` 是**按次总量**、用完即止、永不重置。计数落在 `account_quotas` 表，消耗用一条原子 SQL 完成，避免并发超额。其中 `max_evkeys`（三态：`-1` 不限、`0` 禁止创建、`N` 最多 N 个）与 `max_concurrent_renders` 对**管理组**一律按「不限」执行——服务端折算，面板显示「不限」。

### 额度发放与重置

管理员可在账号列表对某账号「发放额度」：实际额度 = 用户组配额 + 账号级发放额 `granted`。发放额跨周期持久保留、不随惰性重置归零，可发正数补充或负数回收（调整后实际额度必须 ≥ 1）；用户组配额为 0（不限）时发放无意义会被拒绝。「手动重置」只把本周期 `used` 归零、不动已发放额度。人为操作（发放 / 重置）写 `account_quota_logs`，管理端弹窗与用户控制台都能看到；到期自动重置不写流水，避免每个周期首个请求多写一次库。

### 注册与激活码

自助注册**不填激活码**时进入「默认注册用户组」（面板用户组列表点「设为默认」切换，配置项 `REGISTER_DEFAULT_GROUP_ID`；未配置或该组被删则回落并可按需现场重建内置 `Free` 组，从不写死组 id）。**填激活码**时以该码为准：激活码在「用户 → 激活码」标签页里生成（与用户组卡片平齐的独立区块，可按用户组筛选、可删除），生成时选择**目标用户组**，可设**可激活账号数**（`0` = 不限）、**有效日期**（留空 = 码永不过期）、**账号有效期**（自激活当日起 N 天，`0` = 永久）、**到期回落组**（账号到期自动转入该组，留空 = 仅标记过期）与**「允许同一账号反复激活」**（默认关闭，开启后同一账号可重复输入该码、到期日叠加＝续期，每次激活仍照常占一个名额）。注册页的激活码输入框为普通选填项（不折叠），**注册之后也能激活**——登录后在个人控制台「我的会员」卡片输入激活码即可自助升级/续期，卡片同时展示会员到期日与「过期后转入」的用户组名（激活码自身的有效日期不对用户展示）。

注册时必须填**邮箱**（必须含 `@`）。项目**没有邮件服务**，邮箱的唯一用途是「忘记密码」时的凭据，因此不要求全局唯一（多个账号可以填同一个邮箱），也**不展示在账号列表里**——只有点开该账号的「详情」弹窗才可见。登录页底部的「忘记密码」指向 `/admin/reset-password`：填**用户名 + 注册邮箱 + 新密码**，两者同时对得上才允许改密（不发验证码、不发重置链接），失败按独立的 `reset:` 维度计入防撞库；老账号（邮箱为空）需管理员先在「编辑账号」里补邮箱。此外**账号名不区分大小写**（`Admin` 同 `admin`，唯一索引建在 `lower(name)` 上），登录、查重、改名与防撞库计数都按同一口径。

激活码的**生命周期**很短：生成 → 注册或自助激活即核销 → **有限次的码用满、或过了有效日期的码当场销毁**，面板列表只留还能用的码；默认**同一账号对同一张码只能生效一次**（重复输入会明确提示「已使用过」，不会再报一次激活成功，`max_uses = 0` 的码也一样），开启「允许反复激活」后按续期叠加处理。核销与各项上限判定合成一条原子 `UPDATE`，并发注册不会超发；建号/落组失败会归还名额并撤掉核销记录。账号到期归位由启动时与后台刷盘线程周期扫描完成，无需定时任务。内置 `admin` 组的码不可生成、也不可用于注册或自助激活。

### 定时预渲染与成品缓存

管理面板「定时」页可对任意视图/JSON 路由建任务：只填请求路径与查询参数，再选排期（固定间隔，或每日多个 `HH:MM`，按配置时区）。后台按排期渲染成品存入数据库，请求参数完全一致即命中，延迟从「渲染耗时」降到「发文件」。产物按**索引数组 + 调色板**存（PNG 作容器，超 256 色回退 RGB），因此 `rotate` / `invert` / `cmode` / `format` 不进缓存键、命中时按当次请求现场套用，同一次渲染能服务任意 `jpeg/png/webp/tiff/gif/bmp` 与数组格式族（`array` / `bwrarray` / `7carray` 等）请求。缓存寿命按「最后一次被请求」判定（`COALESCE(last_hit_at, rendered_at)`），由既有后台清理周期回收。命中路径不经过 Pillow 重绘，但仍会重跑格式黑名单与用户组权限校验。插件/路由被禁用时任务记 `skipped` 且保留缓存。

### 自动备份

管理面板「备份」页可开启自动备份并填写每日时刻（`HH:MM`，空格或逗号分隔可写多个，如 `03:30 15:00`，按面板时区解释）。到点后做一份整库快照，落到 `data/backups/`——与恢复前自动留的「后悔药」是同一目录，共用同一保留策略（保留份数默认 30、保留天数默认不限）；面板上的「导出数据库」是下载到本机的一次性导出，不落在该目录。多实例部署只有 leader 实例执行，不会重复备份。

### 配置导入 / 导出

管理面板「配置」页新增「导出配置 / 导入配置」两个按钮。导出的是可读 JSON（全局配置项 + 插件配置项 + 各用户组限额 / 配额），可跨实例搬配置、可 diff；与「备份」的分工是：备份是整库快照、用于回滚，配置导出只含配置、用于迁移与比对。导入时会校验包结构、只接受本系统认识的配置项，不认识的项与取值非法的项会被跳过或拒绝并给出摘要，不会整包失败。

### 请求体大小上限

单个请求体超过上限（默认 8MB）直接返回 413，设 `0` 表示不限；仅本地部署生效（Vercel 由平台自身限制）。备份上传另有更宽松的独立上限（默认 64MB），不受这一项影响。

### 请求日志、审计与统计

每个真实插件的请求会写入 `request_logs`（含耗时、状态码、evkey、账号、是否命中预渲染），有**双重上限**：按天保留 + 按总条数淘汰最旧，队列溢出丢弃的条数在日志页可见。管理 API 的写操作（谁 / 何时 / 改了哪个接口 / 结果）记入审计日志 `audit_logs`，敏感字段自动脱敏。统计页提供每路由 p50/p95 与最慢路由榜（按 `cache_hit` 排除预渲染命中，避免把分位拉低）、每日请求图表、状态码分布、启动历史与累计统计。

### 健康检查 `/healthz`

存活探针**只挂在本地链路**，返回 `{"success":true,"status":"ok","mode":...,"version":...}`。它不查库、不渲染、不写请求日志、不占限流额度、不需要 evkey，专供 Uptime Kuma / systemd / Docker healthcheck 轮询——用 `/` 探活会把日志刷满还可能被限流。同时它已进鉴权白名单、限流白名单与日志跳过前缀。

## 架构总览

一次图像请求的完整生命周期如下。Starlette 的 `add_middleware` 是 `insert(0)`，**后注册者在最外层、先执行**，`modules/app_core.py` 按「内层 → 外层」注册，因此实际执行顺序为 `request_log → auth → rate_limit → plugin_disable`；`auth` 必须早于限流与插件开关，否则后者拿不到 `request.state.user_group_id`，用户组限流与权限会静默失效。

```text
客户端 GET /weather/view/summary?size=hxl&evkey=...&rotate=h
        │
        ▼
[1] request_log_middleware      记开始时间；若是 /admin/api 写操作则先取审计摘要
        │
        ▼
[2] auth_middleware             check_auth：Session Cookie → dev 注入用户 → 白名单 → evkey（库 → 环境变量）
        │                       再 _check_admin_api_access 把守 /admin/api（仅本地模式）
        ▼
[3] rate_limit_middleware       账号维度滑动窗口（速率）+ 配额消费（仅本地模式）
        │
        ▼
[4] plugin_disable_middleware   插件开关 → 路由开关 → 用户组插件/路由权限（fail-closed）
        │
        ▼
视图端点（register_view_routes 生成的 /{插件}/view/{种类}）
        │
        ├─ 预渲染命中 → try_serve：先查内存成品缓存（已编码响应体，命中即直出）
        │               未命中才 worker 线程读产物 + 解码索引数组
        │               + 现算 rotate/invert/cmode/format → Response(bytes)（不经 Pillow 重绘）
        │
        └─ 未命中 → 现取模块 plugins.<插件>.view.<种类>.<尺寸>
                    → 账号并发信号量
                    → generate_image()（协程则 await）
                    → save_image() → Response(content=bytes)
        │
        ▼
[1] request_log_middleware 收尾   写 request_logs、插件计数、账号用量；写审计
```

关键环节说明：

1. **白名单**：`AUTH_WHITELIST` 中的路径免鉴权，`'/'` 精确匹配、其余前缀匹配；`RATE_LIMIT_WHITELIST` 与 `_LOG_SKIP_PREFIXES` 各自让静态资源、管理面板、探针不进限流与请求日志。
2. **路由注册**：`register_plugins` 用 `include_router` 前后 `app.router.routes` 的快照差集（按对象身份）记录每个插件新增的路由，供热重载按身份摘除——插件自定义路由不保证挂在 `/<插件>/` 前缀下，不能靠路径猜。框架路由（`random_router`、`template_router`）随后注册。
3. **参数解析**：视图端点调用 `prerender/params.resolve_view_params`，与预渲染任务创建共用同一份实现，保证缓存键与运行时参数一致。参数优先级为 URL 显式参数 > 插件 `plugin_config.py` 默认值 > 全局 `config.py` 默认值。
4. **渲染与并发**：`get_render_semaphore` 按账号缓存信号量（值为 `(组 id, semaphore)`），用户组并发上限优先于全局；无用户身份时用全局上限且不缓存。`mark_start` / `mark_end` 成对打点，异常路径也会收尾。
5. **响应直出**：图像已在内存生成完毕，用 `Response(content=bytes)` 整体返回，**不用 `StreamingResponse` 包 `BytesIO`**——迭代 `BytesIO` 是按行切分而非按块，一张 JPEG 会被拆成上百个小 chunk，单请求凭空多几十毫秒。
6. **命中跳过 Pillow**：预渲染命中时 `try_serve` 先查 `modules/prerender/memcache.py` 的内存成品缓存（存**已编码响应体**，键 = `(缓存键, 格式, 旋转, 反色, cmode)`，按 `PRERENDER_MEMORY_CACHE_MB` 字节预算 LRU），命中即 `Response(bytes)` 直出、既不读库也不解码；未命中才读产物行并解码索引图，再套用本次请求的后处理参数与输出格式，编码结果写回内存缓存。格式黑名单与用户组格式权限**每请求重跑**（在内存缓存之前），因为组权限可能在产物生成后被改掉。只有 `cache_hit` 被标记用于统计口径，渲染打点不会把它算作一次渲染。

## 双入口的差异

`run.py` 是本地完整版（本地测试与自托管生产共用），`app.py` 是专为 Vercel Serverless 的精简入口。二者的能力矩阵：

| 能力 | `run.py`（dev / prod） | `app.py`（vercel） |
| :--- | :--- | :--- |
| 数据库 SQLite | 启用（`data/einkviews.db`，WAL） | 停用（`set_db_disabled(True)`，调用即抛 `DatabaseUnavailable`，连目录都不建） |
| 字体 LRU 缓存 | 启用 | 停用（`set_enabled(False)`，字体每次实时加载） |
| 后台线程 | 有（统计刷盘 + 定时清理 + 预渲染调度） | 无 |
| 请求日志 | 有（`request_log` 中间件） | 无（不注册该中间件） |
| 限流 | 有（`rate_limit` 中间件） | 无 |
| 管理面板 `/admin` | 有 | 无 |
| `/healthz` | 有（`health_router`，仅本地链路注册） | 无 |
| 定时预渲染 / 成品缓存命中 | 有 | 无（整体降级为「没有预渲染」） |
| 首页来源 | `/` 路由读 `public/pages/index.html` 并按 `_LOCAL_BLOCKS` 改写锚点块 | `vercel.json` 把 `/` 直指该静态文件，走边缘直出（完全不经过 Python 函数，零冷启动） |
| 鉴权 | dev 强制关闭；prod 默认开启，由 `AUTH_ENABLE` 控制 | 默认开启，单 key `EVKEY`（未配置则全部 401） |
| 边缘缓存 | 无 | `EDGE_CACHE_TTL`（用 Vercel 独占的 `Vercel-CDN-Cache-Control`，不下发给客户端） |

**为什么默认必须单进程单 worker**：内存限流计数（`rate_limiter`）、字体缓存（`cache`）、渲染打点（`render_metrics`）、登录防撞库（`login_guard`）都只在单进程下全局一致。若给 `uvicorn.run` 加 `workers=N`，限流会变成 N 倍宽松（每个 worker 各记一份）、缓存会分裂成 N 份（命中率下降、内存翻倍），而且**静默失效、不会报错**。因此 `run_core` 的 `uvicorn.run(app, ...)` 禁止加 `workers=N`。要横向扩展就走「多实例 + `REDIS_URL`」（跨实例状态落 Redis，见[部署 · 多实例部署](部署.md#56-多实例部署可选需要-redis)）。

## 技术栈与依赖

依赖只有两个文件，判据只有一句「Vercel 上用不用得到」。`requirements.txt` 是 **Vercel 最小集**：`@vercel/python` 只认这一个文件且装什么就都进函数包，所以里面只放 Serverless 链路 + 插件在 Vercel 上出图真正用得到的，并一律精确锁定版本（`==`）：

| 依赖 | 用途 |
| :--- | :--- |
| `fastapi` | Web 框架与 `APIRouter` 路由体系；应用组装、中间件、异常处理器、自动生成 OpenAPI |
| `httpx` | 异步 HTTP 客户端；规则要求插件所有网络请求使用 `httpx.AsyncClient` 并设置 `timeout` |
| `cachetools` | `LRUCache`（字体缓存）与 `TTLCache`（鉴权缓存、限流计数存储、状态/统计短时缓存） |
| `Pillow` | 图像渲染核心：`P` 模式画布、`ImageDraw` 排版、`textbbox` 测宽、旋转/反色、格式编码 |
| `qrcode` | 二维码生成（`generate_qrcode`），供插件在图上放二维码 |
| `beautifulsoup4` | HTML 解析，供插件抓取网页类数据源时使用 |
| `lunar-python` | 农历/节气计算，供日历类插件使用 |

`requirements-local.txt` 以 `-r requirements.txt` 起头，补上**只有本机进程才用得上**的：

| 依赖 | 用途 |
| :--- | :--- |
| `cachetools` | 字体 LRU 缓存、鉴权缓存、限流滑动窗口、日志统计短时缓存；Vercel 侧缓存停用、鉴权不查库，从不建缓存 |
| `uvicorn[standard]` | ASGI 服务器（含 `uvloop`/`httptools` 等加速件）；本地以安静参数启动（Serverless 由平台托管 ASGI，用不到它） |
| `PyJWT` | 管理面板会话 JWT 的签发与校验（`HS256`）；Vercel 侧只有 evkey 鉴权，不发会话 |
| `redis` | **可选，仅多实例部署**（配置 `REDIS_URL`）时的跨实例共享存储：限流计数、登录防撞库、单例租约、内存态失效广播。单实例完全用不到；未安装或连不上即自动回落进程内存后端 |

第三方依赖只能来自这两个文件。判断该放哪层只问一句「Vercel 上用不用得到」：用不到就不许进 `requirements.txt`——它会被打进函数包、白白撑大体积并拖慢冷启动，`.trae/tests/test_app_smoke.ServerlessEntryTest` 会断言 `app.py` 的导入链没碰它们。`httpx`、`beautifulsoup4`、`lunar-python` 主要为插件预留（插件在 Vercel 上照常出图，所以它们留在最小集里），插件不必自带这些包。原先的 `requirements-multi.txt` 已删除，多实例统一用 `requirements-local.txt`。

## 适用场景与不适用场景

**适用**

- 自托管：一台常开的机器（NAS / 小主机 / 云服务器）跑 `python -B run.py -prod`，为局域网或公网上的多台墨水屏设备出图。
- 需要可视化运维：用管理面板维护用户组与账号、分配 evkey、查看日志与统计、配置定时预渲染。
- 需要成本控制：多设备轮询、需要限流/配额/并发控制，或希望把热门视图预热成「直接发文件」。
- 轻量部署：把无数据库、无状态的 `app.py` 部署到 Vercel，跑纯渲染分发（单 key 鉴权 + 可选边缘缓存）。

**不适用**

- **Vercel 上依赖持久化的能力**：Serverless 无持久存储，数据库、请求日志、统计、管理面板、定时预渲染全部不可用（自动降级），只能把 `app.py` 当无状态渲染函数用。
- **设备端缓存机制**：项目明确不做设备端缓存；Vercel 的边缘缓存用 `Vercel-CDN-Cache-Control`（不下发给客户端），本地模式的图像响应不带缓存头。
- **服务端缓存 HTTP 响应**：图像实时生成，不缓存响应体；字体之外不缓存图片，因为 RGBA 位图会挤掉字体条目。
- **同机多 worker 共享内存状态**：同一进程内的限流、缓存、防撞库、渲染打点不跨进程共享，所以不能靠 `uvicorn --workers=N` 横向扩展——每个 worker 各记一份会让限流悄悄变宽松。要横向扩展请走「多实例 + `REDIS_URL`」：跨实例的限流计数、防撞库、单例租约与失效广播会走 Redis，但渲染并发信号量、字体缓存、预渲染内存成品缓存仍是**每实例各算**（详见[部署 · 多实例部署](部署.md#56-多实例部署可选需要-redis)）。
- **通用 Web UI 或动态网站**：它是一个渲染分发中枢，首页只是入口；业务表现都在插件的图像/JSON 输出里。
- **超 256 色的复杂图像长期预渲染**：产物需回退 RGB PNG，调色板语义丢失，`cmode` 只能近似替换（正常视图不会走到）。
