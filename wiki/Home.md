# eInkViews Wiki

**eInkViews** 是为 [Open ePaper Link](https://github.com/OpenEPaperLink) 设计的墨水屏图像渲染与分发服务。它把「数据 → 排版 → 图像 → 设备拉取」这条链路收敛成一个可自托管、可插件化扩展的服务端，使用 Pillow 做像素级排版，面向多尺寸、多色电子纸输出图像。

当前版本：`26.9.1`（FastAPI + Pillow，全异步）

---

## 它解决什么问题

墨水屏设备端只想要一张已经排好版、尺寸与配色都正确的图。但真实情况是：

- 数据散落在各种来源（天气 API、日历、待办、股票、RSS、随手写的 JSON），格式与刷新频率各不相同；
- 硬件规格不统一，屏幕尺寸从几百像素到上千像素、配色从黑白双色到多色，还有横屏与竖屏之分；
- 设备端算力与内存有限，不适合在设备上做布局与图像处理；
- 同一份数据往往要同时服务多种屏幕、多种输出格式。

eInkViews 的做法是：**把这一切都放在服务端**。每类内容做成一个插件，插件只负责「取数据 + 排版」，路由层统一处理尺寸、调色板、旋转、反色、输出格式、鉴权、限流与配额，设备端只需要一个 HTTP GET。

## 30 秒上手

```bash
pip install -r requirements-local.txt
python -B run.py
```

打开 <http://127.0.0.1:5000/admin> 进入管理面板（dev 模式跳过鉴权、自带 dev 用户）；打开 <http://127.0.0.1:5000/> 是首页。

看重启后是否生效、以及生产环境怎么配，见 [部署](部署.md)。

> 项目约定：所有 Python 命令都要带 `-B`（不生成 `__pycache__`），不要创建虚拟环境。仓库**未固定 Python 版本**（没有 `runtime.txt` / `.python-version` / `pyproject.toml`），但依赖版本全部精确锁定（`==`），用装得上那批版本的 Python 3 即可——详见[部署 · 环境要求与安装](部署.md#2-环境要求与安装)。

## 关键概念速查

| 概念 | 一句话说明 |
| :--- | :--- |
| **插件（plugin）** | `plugins/<名字>/` 下的一个内容来源，自带路由、默认参数、视图与字体资源；改完可用面板「热重载」，不必重启 |
| **视图（view）** | 插件里的一种画面种类，必须分别实现 `hxl` 与 `h2xl` 两种尺寸布局，不能靠缩放复用 |
| **路由（route）** | 请求真正打到的那一条路径，例如 `/<插件>/view/<视图名>?size=hxl`；可单独开关，也可按用户组授权 |
| **账号（account）** | 面板里的一个用户，归属某个用户组；登录面板、申请 evkey 都基于账号。每个账号有对外编号 **UID**（注册顺序，从 10000 起），面板展示与登录都能用它 |
| **UID** | 账号的对外编号，注册时自动分配（10000 起、不设位宽）。登录时填账号名或 UID 都行；纯数字一律按 UID 解释，所以账号名不能是纯数字 |
| **evkey** | 设备端鉴权用的密钥，挂在账号下；同一账号下所有 evkey 共享该账号的额度 |
| **用户组（group）** | 限额与权限的载体：每分钟速率、请求配额 + 配额周期、evkey 上限、最大并发，以及插件/路由级的访问权限。列表里的 ID 是真实主键，删过组后**不复用**，所以编号可能不连续 |
| **配额周期** | `day` / `week` / `month` / `year`（按自然周期到期自动重置）与 `trial`（按次总量，用完即止、永不重置） |
| **额度发放** | 在用户组配额之外，给单个账号额外发的次数，跨周期保留；发负数即回收 |
| **默认注册组** | 自助注册不填激活码时账号进入的用户组，在用户组列表点「设为默认」切换（配置项 `REGISTER_DEFAULT_GROUP_ID`） |
| **激活码** | 在「用户 → 激活码」标签页生成并可选择目标用户组，注册时填入即进入该组（注册后也可在个人控制台「我的会员」里输入，自助升级/续期）；可设可激活账号数、有效日期、账号有效期、到期回落组与**「允许同一账号反复激活」**开关。默认同账号同一张码只能生效一次；开启该开关后为续期语义（到期日叠加），每次激活仍占一个名额。有限次的码用满或过期的码当场销毁 |
| **预渲染（prerender）** | 定时把变化慢的视图提前渲染成成品图存库，参数完全一致的请求直接命中，延迟从「渲染耗时」降到「发文件」 |
| **成品缓存** | 预渲染产物按索引数组存库，一份产物可服务任意旋转 / 反色 / 输出格式 |

> 贯穿全项目的数值约定：**`0` = 不限 / 不过期 / 不限制**。唯一的例外是 evkey 上限——那里 `-1` = 不限、`0` = 禁止创建、`N` = 最多 N 个。

## 三种运行形态

| | 本地开发 | 自托管生产 | Vercel Serverless |
| :--- | :--- | :--- | :--- |
| 启动 | `python -B run.py` | `python -B run.py -prod` | `app.py` |
| 鉴权 | 强制关闭，注入 dev 用户 | 默认开启（可用 `AUTH_ENABLE=0` 关） | 默认开启，比对 `EVKEY` |
| 数据库 / 缓存 / 管理面板 | 全部启用 | 全部启用 | 全部停用 |
| 首页 | `/` 走 Python 路由并改写本地化文案 | 同左 | `/` 由 `vercel.json` 指到静态文件，走边缘 |

完整对比与部署步骤见 [部署](部署.md)。

## 仓库目录一览

```text
einkViewsEvo/
├── run.py                    # 本地入口（dev / prod）与启动编排
├── app.py                    # Vercel Serverless 入口
├── config.py                 # 全局默认配置
├── vercel.json               # Vercel 路由与静态直出
├── assets/fonts/             # 全局字体
├── data/                     # SQLite 数据库（自动创建，不可对外静态暴露）
├── modules/                  # 框架代码：应用组装（app_core / run_core）、数据库、鉴权、缓存、管理面板、预渲染
├── plugins/                  # 插件：每个子目录一个内容来源
├── public/                   # 静态资源与首页
└── .trae/                    # 项目配置目录
    ├── tests/                # 标准库 unittest 用例
    ├── rules/                # 项目规则
    ├── wiki/                 # 本 wiki 的 Markdown 源文件
    └── documents/            # 设计与实施方案
```

各目录下每个子模块的职责，见 [介绍](介绍.md) 的模块职责表。
