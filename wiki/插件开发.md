# 插件开发

本页面向要**新增一个插件**的开发者。eInkViews 的插件是一段放在 `plugins/<插件名>/` 下的独立代码：框架会在启动时扫描目录，把每个插件的路由挂到应用上，请求到来时再按 `view/<种类>/<尺寸>.py` 的路径动态导入视图模块，渲染出墨水屏图像。

读完本页，你应该能照着 `plugins/plugin_template/` 复制出一份可运行的新插件。所有示例都与仓库里的真实函数签名一致，请以代码为准；个别示例为节省篇幅做了删减，完整版一律指向仓库里的真实文件。

**本页怎么读**：第 1 节是**照做**的教程，跟着走一遍就能拿到一个能出图、能热重载的插件（一行代码都不用自己写）；第 2 节起是**参考手册**，按需查。第一次读不必从头看到尾。

---

## 0. 读之前：先把四个词分清楚

后面全靠这四个词，先把它们对上号，再往下读就不会卡：

| 词 | 是什么 | 在代码里的位置 | 在 URL 里的样子 |
| :--- | :--- | :--- | :--- |
| **插件（plugin）** | 一类内容来源，比如「天气」。一个插件 = `plugins/<插件名>/` 一个目录 | `plugins/weather/` | URL 的第一段 `/weather/...` |
| **视图种类（kind）** | 这个插件的一种**画法**，比如「概要图」与「详图」。画法不同就得各写一套 | `view/<kind>/` 的**目录名** | `/weather/view/summary` 里的 `summary` |
| **尺寸（size）** | 画布规格，如 `hxl` = 384×184、`h2xl` = 400×300 | `view/<kind>/<size>.py` 的**文件名** | `?size=hxl` |
| **路由（route）** | 上面三个拼出来的那条可请求路径 | 框架自动注册，你不用手写 | `/weather/view/summary?size=hxl` |

一句话记法：**一条视图路由 = `/<插件名>/view/<kind>?size=<size>`**，它最终执行的是 `plugins/<插件名>/view/<kind>/<size>.py` 里的 `generate_image()`。

插件一共能挂三类路由，都由**目录里的内容**自动生成，同样不用手写：

| 想输出什么 | 放哪 | 自动生成的路由 | 必须暴露 |
| :--- | :--- | :--- | :--- |
| 一张墨水屏图 | `view/<kind>/<size>.py` | `/<插件>/view/<kind>?size=<size>` | `generate_image(...)` |
| 一份 JSON（调试 / 联调） | `json_module/<名>.py` | `/<插件>/json/<名>` | `to_json(**kwargs)` |
| 一个静态网页 | `page/<名>.html` | `/<插件>/page/<名>` | （无，直出文件） |

**框架是怎么发现插件的**：启动时扫描 `plugins/` 下的每个子目录，**只要该目录里有 `routes.py`，这个插件就会被加载**。不需要登记表，也不需要改框架代码。

## 1. 从零跑通一个插件

这一节是**照做**的，每一步都配了验收动作。做完你会得到一个能出图的新插件；第 2 节起才是按需查的参考手册。

整节只用到两样东西：仓库里的模板 `plugins/plugin_template/`，以及本地 dev 服务。

### 1.1 先把服务跑起来

```bash
pip install -r requirements-local.txt
python -B run.py
```

看到启动摘要打印出 `管理面板: http://127.0.0.1:5000/admin` 就算起来了。

> 两条项目硬性约定：**不要创建虚拟环境**（不要 `venv` / `conda` / `virtualenv`）；**所有 Python 命令都带 `-B`**（不生成 `__pycache__`）。仓库**未固定 Python 版本**（没有 `runtime.txt` / `.python-version` / `pyproject.toml`），用装得上那批锁定依赖的 Python 3 即可，详见[部署 · 环境要求与安装](部署.md#2-环境要求与安装)。

### 1.2 复制模板

```powershell
Copy-Item -Recurse plugins\plugin_template plugins\myweather
```

```bash
cp -r plugins/plugin_template plugins/myweather
```

### 1.3 改名：三处必须一起改（最容易漏的一步）

复制完**必须**把下面三处的名字改成新目录名 `myweather`。漏掉任何一处都跑不起来，其中第 2 处最难自查：

| # | 位置 | 改成什么 | 漏改的后果 |
| :--- | :--- | :--- | :--- |
| 1 | 目录名 | `plugins/myweather/` | — |
| 2 | `routes.py` 里的 `PLUGIN_NAME` | `PLUGIN_NAME = "myweather"` | **新插件的路由根本不存在**：`/myweather/view/summary` 返回 404，而 `/plugin_template/view/summary`（模板本身）照旧出图。偏偏面板里能看到 `myweather` 已加载——最容易误判成「插件没生效」 |
| 3 | `plugin.json` 的 `"name"` | `"name": "myweather"` | 插件加载失败，面板插件页显示原因 |

**为什么第 2 处这么要命**：`PLUGIN_NAME` 同时决定两件事——路由前缀（`register_view_routes` 用 `f'/{plugin_name}/view/{kind}'` 拼路径）和视图模块的导入路径（`importlib.import_module(f'plugins.{plugin_name}.view.{kind}.{size}')`）。所以 **`PLUGIN_NAME` 必须与插件目录名逐字一致**。这三处是同一个名字的三份拷贝，改目录名时请一起改。

> 顺带一提：如果你是**改名**而不是复制（把 `plugin_template/` 目录直接改掉），那么第 2 处的后果会变成导入失败——400「视图 plugin_template.view… 不存在」，报错里出现的是模板名，同样难自查。

顺手把 `routes.py` 的 `PLUGIN_DESCRIPTION` 也改成你自己的中文描述（它只是 `plugin.json` 没写 `description` 时的兜底，改不改都能跑）。

### 1.4 确认插件被加载了

打开 `http://127.0.0.1:5000/admin` →「插件」标签页，确认列表里出现了 `myweather`。

**没出现怎么办**：插件导入失败时**不会**出现在列表里，只会被计入 `failed`，失败原因写在 `failures`（面板会展示，形如 `{'name': ..., 'error': ...}`）。十有八九是 1.3 节那三处名字没对齐——尤其是 `plugin.json` 的 `name` 与目录名不一致。

### 1.5 请求一下，看到图

```text
http://127.0.0.1:5000/myweather/view/summary?size=hxl&title=Hello
```

浏览器会直接显示一张 384×184 的图。换尺寸、换视图、看 JSON：

```text
http://127.0.0.1:5000/myweather/view/summary?size=h2xl
http://127.0.0.1:5000/myweather/view/detail?size=hxl&b=changed
http://127.0.0.1:5000/myweather/json/demojson?a=alpha
```

> 模板的 `page/` 目录是空的（只有 `__init__.py`），所以现在还没有 `/myweather/page/...` 这条路由。想要页面路由，往 `page/` 放一个 `.html` 即可，见第 7 节。
>
> 测试 URL 必须写**完整地址**（`http://127.0.0.1:5000/...`），且**不要带 `palette` 参数**。

到这一步你一行代码都没写，跑的还只是模板的复制品。下面开始改。

### 1.6 改一行，看变化

改 `plugins/myweather/lib/demo_data.py` 里 `build_demo_data()` 的返回值，比如把 `"subtitle"` 的默认值换掉；刷新 1.5 节那条 URL，图上的副标题应该跟着变。

**改了却没变，就是模块缓存没清**——看下一节。

### 1.7 热重载

改了 `plugins/**` 下的代码不必重启服务：到面板「插件」页点 **「热重载」**，或直接：

```bash
curl -X POST http://127.0.0.1:5000/admin/api/plugins/reload
```

返回 `{success, total, loaded, failed, failures}`。刷新 URL 就能看到新效果。

> 热重载**只覆盖 `plugins/**`**。改了 `modules/**`（框架代码）必须重启进程。

## 2. 插件目录结构与约定

真实脚手架位于 `plugins/plugin_template/`，推荐结构如下（以模板为准）：

```text
plugins/
└── plugin_template/
    ├── __init__.py            # 插件脚手架：允许只放 docstring
    ├── README.md              # 插件自己的说明与测试链接
    ├── routes.py              # 必须暴露 router / PLUGIN_NAME / PLUGIN_DESCRIPTION，只做路由装配
    ├── plugin.json            # 插件清单：元信息的唯一来源（版本、描述、作者、依赖…）
    ├── plugin_config.py       # 插件默认参数（DEFAULT_ARGS / DEFAULT_ROTATE / DEFAULT_INVERT）与配置项显示名
    ├── lib/
    │   ├── __init__.py
    │   └── demo_data.py       # 参数 → 可展示数据（取数、构造结构都放这里）
    ├── json_module/
    │   ├── __init__.py
    │   └── demojson.py        # 必须暴露 to_json(**kwargs)，返回结构化 JSON
    ├── page/
    │   ├── __init__.py
    │   └── index.html         # 每个 .html 自动注册一条 /<插件>/page/<名> 路由（静态直出；模板未带，按需新建）
    └── view/
        ├── __init__.py
        ├── summary/           # 一个“视图种类”一个目录
        │   ├── __init__.py
        │   ├── hxl.py         # 必须暴露 generate_image(...)
        │   ├── h2xl.py        # 必须暴露 generate_image(...)，独立布局
        │   └── utils.py       # 该种类内部复用的测量/排版辅助函数
        └── detail/
            ├── __init__.py
            ├── hxl.py
            ├── h2xl.py
            └── utils.py
```

各文件职责：

- `routes.py`：只做路由装配，不写业务逻辑。它调用三个工具函数把 `view/`、`json_module/`、`page/` 下的模块批量注册成路由。
- `plugin.json`：插件清单，**元信息（名称、版本、描述、作者、最低框架版本、依赖）的唯一来源**，字段全部可选。
- `plugin_config.py`：插件级默认参数与默认旋转/反色，以及面板「插件配置」里显示的可读名称。建议只放真正需要的默认值。
- `lib/`：把参数转换成可展示的数据（含网络取数）。视图层只消费这里的结果，不再做复杂判断。
- `json_module/`：输出结构化数据，便于调试、集成和联调。
- `view/<kind>/`：负责绘制图像。**一个视图种类对应一个模块目录**，不要把多个种类塞进同一个模块。
- `page/`：静态 HTML 页面，原样直出（没有模板引擎）。给插件配说明页 / 预览页用，见第 7 节。

**哪些目录是必须的**：只做 JSON 接口的插件可以只有 `routes.py` + `plugin_config.py` + `json_module/`——三个 `register_*` 函数发现目录不存在时直接返回，不会报错。但**只要做了视图，`hxl` 与 `h2xl` 必须都实现**（见第 5 节的硬性排版规则）。`plugin.json` 也不是必须的，缺了只是面板显示「未声明清单」。

### `__init__.py` 的约定（重要区别）

- `plugins/**` 下的 `__init__.py` 属于**插件脚手架**，允许只放一行 docstring，例如模板里的：

  ```python
  """Plugin template for eInkViews."""
  ```

- `modules/**` 下的 `__init__.py` **必须为空文件**，实现代码一律放在具名子模块里，导入时写完整子模块路径。

插件内部的分包也遵循同样思路：`lib/`、`view/<kind>/` 都各有一个 `__init__.py`。

## 3. `routes.py` 的契约

`routes.py` 必须暴露三个名字：

- `router = APIRouter()`：所有路由都挂在它上面。
- `PLUGIN_NAME`：插件名。**必须与插件目录名逐字一致**——它既当路由前缀，又当视图/JSON 模块的导入路径。改目录名时别忘了改这里（见 [1.3 改名](#13-改名三处必须一起改最容易漏的一步)）。
- `PLUGIN_DESCRIPTION`：插件的中文描述。**只作为兜底**：面板显示的描述优先取 `plugin.json` 的 `description`，只有没写清单（或清单没写描述）时才回落到这个常量，两者都没有才显示 `'无描述'`。

真实可用的最小示例（与 `plugins/plugin_template/routes.py` 一致）：

```python
from fastapi import APIRouter
import os
from modules.register.auto_view_routes import register_view_routes
from modules.register.auto_json_routes import register_json_routes
from modules.register.auto_page_routes import register_page_routes

PLUGIN_NAME = "plugin_template"
PLUGIN_DESCRIPTION = "插件模板"

router = APIRouter()
plugin_dir = os.path.dirname(os.path.abspath(__file__))

register_view_routes(router, PLUGIN_NAME, os.path.join(plugin_dir, "view"))
register_json_routes(router, PLUGIN_NAME, os.path.join(plugin_dir, "json_module"))
register_page_routes(router, PLUGIN_NAME, os.path.join(plugin_dir, "page"))
```

注意路径一律用 `os.path.join(os.path.dirname(__file__), ...)` 拼接，不要写死绝对路径。

### 自动注册出来的路由与端点名

三个工具函数会按目录内容自动生成路由：

| 工具函数 | 扫描目录 | 生成的路由 | 端点名 | 被调用的函数 |
| :--- | :--- | :--- | :--- | :--- |
| `register_view_routes` | `view/` 下每个子目录 | `GET /<插件>/view/<kind>` | `view_<插件>_<kind>` | `generate_image(...)` |
| `register_json_routes` | `json_module/*.py`（跳过 `_` 开头） | `GET /<插件>/json/<名>` | `json_<插件>_<名>` | `to_json(**kwargs)` |
| `register_page_routes` | `page/*.html` | `GET /<插件>/page/<名>` | `page_<插件>_<名>` | 直接返回该 HTML 文件 |

`register_view_routes` 会跳过 `_` / `.` 开头的目录（否则会注册出 `/插件/view/__pycache__` 这种幽灵路由）。视图路由的 `<kind>` 就是目录名。

### 插件自定义路由不保证挂在 `/<名字>/` 下

你可以在 `routes.py` 里直接给 `router` 加任意路由，路径不必带插件名前缀。框架据此做了刻意的设计约束：

- `register_plugins` 用「`include_router` 前后 `app.router.routes` 的**对象身份快照差集**」记录本插件新增的路由（存进 `app.state.plugin_routes[插件名]`），**禁止靠路径前缀猜**。
- 热重载 `reload_plugins` 按这个记录按身份摘除旧路由，再重新扫描注册。

结论：你新增自定义路由时**不要**试图用路径前缀去让框架“认领”它，框架本来就能正确跟踪。你只需保证路由挂在 `router` 上，并记得 `include_router` 是在 `routes.py` 被导入时执行的。

## 4. `plugin.json` 清单与 `plugin_config.py` 参数

### `plugin.json`：元信息的唯一来源

位置 `plugins/<插件名>/plugin.json`，与 `routes.py` 同级。字段**全部可选**，缺失按默认值处理：

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| `name` | 字符串 | 插件名，**必须与目录名一致**，不一致会加载失败 |
| `version` | 字符串 | 点分版本号，如 `1.0.0` |
| `description` | 字符串 | 插件描述，面板显示的就是这里的内容 |
| `author` | 字符串 | 作者 |
| `min_framework_version` | 字符串 | 点分版本号；高于当前框架版本时插件被跳过并记录原因 |
| `dependencies.plugins` | 字符串数组 | 依赖的其它插件名，被依赖者先加载 |
| `dependencies.python` | 字符串数组 | 建议依赖的 Python 包；只记录不强制 |

模板里真实存在的这份清单长这样（只有 11 行，可以直接照抄改）：

```json
{
  "name": "plugin_template",
  "version": "1.0.0",
  "description": "示例插件，演示视图 / JSON 路由的最小实现",
  "author": "",
  "min_framework_version": "26.9.0",
  "dependencies": {
    "plugins": [],
    "python": []
  }
}
```

**`name` 必须与插件目录名逐字一致**，否则插件加载失败。它和 `routes.py` 里的 `PLUGIN_NAME` 是同一个名字的两份拷贝，改目录名时三处一起改（见 [1.3 改名](#13-改名三处必须一起改最容易漏的一步)）。

`min_framework_version` 只在**真的要拦住低版本框架**时才填：它高于当前框架版本时插件会被跳过（不是加载失败），面板显示原因。

字段值类型不对、版本号格式非法、或 `name` 与目录名不一致 → 插件加载失败并在面板显示原因；没有这份清单也不会被拒绝加载，只是面板显示「未声明清单」。**面板与启动摘要一律只看清单，不再从插件代码的常量里取版本、作者、依赖**，所以元信息不要再写进 `plugin_config.py`。

### `plugin_config.py`：默认参数

`plugin_config.py` 里定义插件默认值与配置项的显示名，模板内容如下：

```python
# 配置项的可读名称与说明（面板「插件配置」弹窗用）。
# 未登记的键回落到显示原始键名，所以新增配置项时记得在这里补一行。
CONFIG_LABELS = {
    "DEFAULT_ARGS": {
        "label": "默认参数",
        "desc": "视图 / JSON 的默认查询参数；URL 显式传了的参数以 URL 为准",
    },
    "DEFAULT_ROTATE": {"label": "默认旋转角度", "desc": "0 / 90 / 180 / 270"},
    "DEFAULT_INVERT": {"label": "默认反色", "desc": "开启后默认反色显示"},
}

DEFAULT_ARGS = {
    "a": "alpha",
    "b": "beta",
    "title": "Demo Template",
    "subtitle": "Generic plugin skeleton",
    "left": "Left block",
    "right": "Right block",
    "note": "Use utils.py for reusable layout helpers.",
    "tz": None,
}
DEFAULT_ROTATE = 0
DEFAULT_INVERT = False
```

- `DEFAULT_ARGS`：业务参数默认值。
- `DEFAULT_ROTATE` / `DEFAULT_INVERT`：仅当 URL 没传 `rotate` / `invert` 时生效。
- `CONFIG_LABELS`：**声明**用途，本身不是配置项。面板「插件配置」弹窗据此显示中文名与说明；只允许对已声明的配置项写标签，多写的会被丢弃。

面板的配置面**只列 `plugin_config.py` 里的真值类型配置项**：`PLUGIN_NAME` / `PLUGIN_DESCRIPTION` / `CONFIG_LABELS` 这类声明、下划线开头的私有名、以及 `import` 带进来的模块名都不会出现在弹窗里，也不能被写成覆盖值。因此元信息常量请只写在 `plugin.json`。

面板按取值类型给不同的编辑方式：布尔值给开关，字符串 / 数字给行内输入框，**字典与数组（如 `DEFAULT_ARGS`）行内只显示一段只读预览，点「编辑」在弹窗里的等宽文本框中改 JSON**——JSON 挤进行内单行输入框既看不全也改不动。所以配置项尽量用小写键名放进 `DEFAULT_ARGS`，不要另外定义一层嵌套结构；确实需要嵌套时，弹窗里的文本框会做格式校验并在出错时给出具体原因。

### 参数优先级

```text
URL 显式参数  >  插件 plugin_config.py 默认值  >  全局 config.py 默认值
```

实际的合并发生在 `modules/prerender/params.py` 的 `resolve_view_params()`：先取 `get_plugin_default_args()`，再 `update` 上 URL 里**除保留项之外**的全部查询参数。保留项是 `size` / `rotate` / `invert` / `cmode` / `format`，由路由层单独解析，不会透传给视图。

- `size`：必需。缺了抛 `ParamError('缺少 size 参数')`，形状不像模块名（`hxl.py` / `../hxl` / `_hxl`）抛 `ParamError('size 参数不合法')`（均 400）。
- `rotate`：URL 取值 `c`→270°、`cc`→90°、`h`→180°，非法值抛 `ParamError('rotate 参数必须为 c / cc / h')`；没传时回落到 `DEFAULT_ROTATE`，再回落到 `config.DEFAULT_ROTATE`。
- `invert`：URL 取值 `t`/`f`，非法值抛 `ParamError('invert 参数必须为 t 或 f')`；没传时回落到 `DEFAULT_INVERT`，再回落到 `config.DEFAULT_INVERT`。
- `format`：映射为 `fmt`，缺省 `config.DEFAULT_IMAGE_FORMAT`（默认 `jpg`）。
- `cmode`：URL 取值 `2bw` / `r2y` / `y2r` / `yr2r` / `yr2y` / `None`，非法值抛 `ParamError('cmode 参数必须为 …')`；没传时回落到插件 `DEFAULT_ARGS` 的 `cmode`，再回落到 `config.DEFAULT_CMODE`。

> **URL 显式传的保留参数一律严格校验：拼错就 400，不会静默按默认值出图。** 判定集中在 `modules/prerender/params.py` 的 `parse_rotate_arg` / `parse_invert_arg` / `parse_cmode_arg`，`/random/views` 与视图路由共用这一份（插件的 `DEFAULT_ROTATE` / `DEFAULT_CMODE` 属配置错误，不在请求期报 400）。

### 禁止在导入期捕获配置值

框架支持**热更新**：全局配置改动靠 `setattr(config, ...)` / `importlib.reload(config)` 生效，插件配置改动靠 `clear_plugin_config_cache()`（`plugin_loader` 里配置项与标签共用一个缓存的唯一失效入口）。因此：

- **禁止**写 `X = config.Y` 这种模块导入期快照；必须在使用时现取（`getattr(config, ...)` 或函数内 `import config` 后再取）。
- 插件 `DEFAULT_ARGS` **一律经 `get_plugin_default_args(plugin_name, plugin_dir)` 取**，它会做类型兜底：非字典一律按空字典处理，避免下游 `dict()` 直接抛错。
- 视图里**不要**自己去读 `plugin_config.py`；请接受框架已经合并好的参数。视图只负责取数与排版，不做参数降级。

## 5. 视图实现规范

视图模块 `view/<kind>/<size>.py` 必须暴露：

```python
def generate_image(rotate=0, invert=False, tz=None, cmode=None, **kwargs):
    ...
```

框架的调用方式（见 `modules/register/auto_view_routes.py`）是：

```python
img = mod.generate_image(rotate=rotate, invert=invert, cmode=cmode, **params)
```

`params` 是合并后的业务参数（含 `tz`，如果 URL 传了的话）。`rotate` / `invert` / `cmode` 由路由层单独解析后传入，所以视图签名里把它们单独列出来。

### 一个完整的 `hxl` 示例

要点：**先取数据，再创建画布**；文本测量一律 `draw.textbbox()`；所有绘制前做边界检查。

下面这份是节选（省掉了 `draw_rows` 画表格行与右下角补注的部分，三段调用各有各的作用），完整版见 `plugins/plugin_template/view/summary/hxl.py`——建议直接读那个文件，它同时还示范了「多行成组绘制」该怎么写。

```python
import importlib

canvas_factory = importlib.import_module("modules.generate_views.canvas_factory")
create_canvas = canvas_factory.create_canvas
finalize_image_common = canvas_factory.finalize_image_common

from ...lib.demo_data import build_demo_data
from .utils import load_font, draw_safe_text, text_size


def generate_image(rotate=0, invert=False, tz=None, cmode=None, **kwargs):
    # 1) 先取数据
    data = build_demo_data(
        a=kwargs.get('a'),
        b=kwargs.get('b'),
        tz=tz,
        title=kwargs.get('title'),
        subtitle=kwargs.get('subtitle'),
        left=kwargs.get('left'),
        right=kwargs.get('right'),
        note=kwargs.get('note'),
    )

    # 2) 再创建画布（SIZES 见 modules/generate_views/canvas_factory.py）
    img, draw = create_canvas('hxl', palette_type='bwr', cmode=cmode)

    title_font = load_font(32)   # 核心标题 32px
    body_font = load_font(16)    # 次要信息 16px

    # 3) 用 textbbox() 测量 + 边界检查后再绘制
    draw_safe_text(draw, (16, 10), str(data['meta']['title']),
                   fill=2, font=title_font, img_width=img.width, img_height=img.height)
    draw_safe_text(draw, (16, 44), str(data['meta']['subtitle']),
                   fill=1, font=body_font, img_width=img.width, img_height=img.height)

    return finalize_image_common(img, rotate=rotate, invert=invert)
```

模板里 `view/<kind>/utils.py` 提供 5 个辅助函数，都值得直接复用——它们的共同点是**绘制前先量尺寸、越界就贴边收回来，绝不硬画**：

| 函数 | 作用 |
| :--- | :--- |
| `load_font(size)` | 按字号取字体，失败回落 `ImageFont.load_default()` |
| `text_size(draw, text, font)` | 用 `textbbox()` 量出 `(宽, 高)` |
| `draw_safe_text(draw, xy, text, fill, font, img_width, img_height)` | 画一行文字，越界自动贴边 |
| `draw_label_value(...)` | 画「标签 + 值」一段（标签可单独上红色），返回本行高度 |
| `draw_rows(draw, x, y, rows, ...)` | 把多组「标签 + 值」按行铺开，自动累加 `y` |

前两个的源码：

```python
def text_size(draw, text, font):
    bbox = draw.textbbox((0, 0), str(text), font=font)
    return bbox[2] - bbox[0], bbox[3] - bbox[1]


def draw_safe_text(draw, xy, text, fill, font, img_width, img_height):
    x, y = xy
    text = str(text)
    tw, th = text_size(draw, text, font)
    if x + tw > img_width:
        x = max(0, img_width - tw - 2)
    if y + th > img_height:
        y = max(0, img_height - th - 2)
    if x < 0:
        x = 0
    if y < 0:
        y = 0
    draw.text((x, y), text, fill=fill, font=font)
    return tw, th
```

### 硬性排版规则

- **同一视图种类必须分别实现 `hxl` 与 `h2xl`**，且 `h2xl` **必须独立布局，不能简单缩放 `hxl`**。模板里两个文件的坐标、面板位置都不同，就是范例。
- 字号**必须是 16 的整数倍**。
- 核心标题或大数值建议 **32px 以上**；次要信息建议 **16px**。
- 画面要**分区清晰、留白充足**、信息密度适中。
- **红色只用于标题、警示或核心数据**，不要滥用。在 `palette_type='bwr'` 的三色画布上，红色索引是 `2`，黑色是 `1`，白色是 `0`。
- **黑色必须显式写 `fill=1` 或 `fill=(0, 0, 0)`，禁止 `fill=0`**（`0` 是白色）。
- 默认只做横屏视图，除非用户明确要求竖屏。
- `create_canvas(size_key, palette_type, cmode=None)` 只认 `SIZES` 里的键（`m` / `hl` / `hxl` / `h2xl` / `h3xl` / `h4xl` 及竖屏版本），并且**必须指定调色板**，否则抛 `ValueError`。用完后调 `finalize_image_common(img, rotate=rotate, invert=invert)` 做旋转/反色并转成 RGB 返回。
- **视图用哪个调色板，就天然支持哪个数组格式**：`bw` → `array`/`bwarray`（1bpp）、`bwr`/`bwy` → `bwrarray`/`bwyarray`、`bwry` → `bwryarray`（2bpp）、`7color` → `7carray`（3bpp）。颜色在目标调色板里没有时按 `cmode` 规则降级（`r2y` → `y2r` → `yr2r` → `yr2y` → `2bw`），视图侧不需要为数组格式做任何额外处理。

## 6. JSON 模块（`json_module/`）

同一个插件的「图」和「数据」应当来自同一份取数逻辑：把取数放 `lib/`，视图与 JSON 模块都去调它。JSON 路由是给调试与联调用的，不是必需品——不需要就不建这个目录。

### 契约

`json_module/` 下的每个 `.py`（跳过 `_` 开头的）自动注册一条 `GET /<插件>/json/<文件名>` 路由，模块必须暴露：

```python
def to_json(**kwargs):
    ...
```

- 路由层的调用方式是 `mod.to_json(**params)`，`params` 是**归一化后的全部查询参数**。与视图路由不同，JSON 路由**没有 `size` 这个必需项**，也不解析 `rotate` / `invert` / `cmode` / `format`。
- 返回值必须能被 `JSONResponse` 序列化（dict / list 等 JSON 原生类型）。返回不可序列化的对象会在响应阶段报错。
- 模块导入失败（语法错误 / 缺依赖 / 模块级异常）与未实现 `to_json` 都抛 `ParamError`（400），且错误文案里带完整模块路径，便于定位。

### 完整示例

模板里的实现只有 5 行——把取数委托给 `lib/`，这是推荐写法：

```python
# plugins/myweather/json_module/demojson.py
from ..lib.demo_data import build_demo_data


def to_json(**kwargs):
    return build_demo_data(**kwargs)
```

验证：

```text
http://127.0.0.1:5000/myweather/json/demojson?a=alpha
```

### 与视图的关系

两边读同一份 `lib/`，所以「图上的数字」与「JSON 里的数字」不会对不上。视图侧是 `generate_image(**params)`、JSON 侧是 `to_json(**params)`，参数分别由 `resolve_view_params` / `resolve_json_params` 归一化，优先级同一套规则（见第 4 节）。JSON 路由同样支持预渲染命中（见第 12 节）。

## 7. 静态页面（`page/`）

`page/` 下的每个 `.html` 自动注册一条 `GET /<插件>/page/<文件名>` 路由，直接返回该文件。

- **没有模板引擎**：实现是 `FileResponse(file_path)` 原样直出——不渲染 Jinja2、不做变量替换。需要动态内容，就让页面里的 JS 去调本插件的 JSON 路由。
- **只扫描 `page/` 下一层**，不递归子目录。
- 用途：给这个插件配说明页、预览页或调试面板。

### 完整示例

模板的 `page/` 里没有现成文件，下面是你要**新建**的 `plugins/myweather/page/index.html`：

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="utf-8">
  <title>myweather 预览</title>
</head>
<body>
  <h1>myweather</h1>
  <img src="/myweather/view/summary?size=hxl" alt="概要图">
  <pre id="out"></pre>
  <script>
    fetch('/myweather/json/demojson').then(function (r) { return r.json() })
      .then(function (d) { document.getElementById('out').textContent = JSON.stringify(d, null, 2) });
  </script>
</body>
</html>
```

访问 `http://127.0.0.1:5000/myweather/page/index`。

## 8. 数据获取（异步）

所有网络请求用 `httpx.AsyncClient`，**必须设置 `timeout`**。Pillow 操作保持同步即可。

取数放在 `lib/` 里，视图通过 `await` 调用。一个真实风格的示例：

```python
# plugins/myplugin/lib/fetch.py
import httpx


async def fetch_metrics(city, tz=None):
    timeout = httpx.Timeout(5.0)
    async with httpx.AsyncClient(timeout=timeout) as client:
        resp = await client.get(
            "https://api.example.com/metrics",
            params={"city": city},
        )
        resp.raise_for_status()
        return resp.json()
```

对应的视图（注意 `async def` 与“先取数据、再创建画布”的顺序）：

```python
import importlib

canvas_factory = importlib.import_module("modules.generate_views.canvas_factory")
create_canvas = canvas_factory.create_canvas
finalize_image_common = canvas_factory.finalize_image_common

from ...lib.fetch import fetch_metrics
from .utils import load_font, draw_safe_text


async def generate_image(rotate=0, invert=False, tz=None, cmode=None, **kwargs):
    data = await fetch_metrics(kwargs.get('city', 'beijing'), tz=tz)

    img, draw = create_canvas('hxl', palette_type='bwr', cmode=cmode)
    title_font = load_font(32)

    draw_safe_text(draw, (16, 10), str(data.get('title', 'Metrics')),
                   fill=2, font=title_font, img_width=img.width, img_height=img.height)

    return finalize_image_common(img, rotate=rotate, invert=invert)
```

`register_view_routes` 用 `inspect.iscoroutinefunction()` **自动检测** `generate_image` 是否为协程，同步/异步两种写法都兼容；有网络请求时请写成 `async def`。预渲染调度同样兼容两者（同步版会被丢到线程池执行）。

### 时间一律用 `modules/utils/timezone.py`

不要直接用 `datetime.now()`，请使用框架提供的函数，它们会自动套用 `config.DEFAULT_TIMEZONE_OFFSET` 或 URL 传来的 `tz`：

```python
from modules.utils.timezone import now_in_timezone, utc_now_iso

now = now_in_timezone(tz)          # 带时区的当前时间
stamp = utc_now_iso()              # UTC ISO 字符串，用于会话/日志时间戳
```

其它可用函数：`convert_utc_to_local(dt_utc, param_offset=None)`、`utc_string_to_local(value, fmt=..., param_offset=None)`、`get_timezone_offset(param_offset=None)`。

## 9. 字体、图标与图片资源

### 字体

- **全局字体只从项目根目录 `assets/fonts/` 读取**（现有 `font.ttf`、`sunnyclock.ttf`、`weather-icon.ttf`）。
- **插件私有字体只从插件自己的 `assets/fonts/` 读取**。
- 字体加载必须走缓存 API，避免重复解析。路径工具在 `modules/generate_views/font_loader.py`：

```python
from modules.generate_views.font_loader import get_root_font_path, get_font

font = get_font(32, get_root_font_path("font.ttf"))   # 签名是 (size, font_path)
```

模板里 `view/<kind>/utils.py` 的 `load_font(size)` 就是对它的薄封装，并在失败时回落 `ImageFont.load_default()`：

```python
def load_font(size):
    try:
        return get_font(size, get_root_font_path("font.ttf"))
    except Exception:
        return ImageFont.load_default()
```

插件私有字体路径用 `get_plugin_font_path(filename, base_file)`：它从 `base_file` 所在目录**上溯两级**得到插件根目录。因此 `base_file` 传 `__file__` 时，最典型的使用位置是 `view/<kind>/xxx.py`（`view/<kind>` 上溯两级正好是插件根）；放在 `lib/xxx.py` 里上溯两级会落到 `plugins/`，请避免在那里调用。

注意底层与封装层的参数顺序不同：`modules/cache/cache.get_font(font_path, size)`，而上层的 `modules/generate_views.font_loader.get_font(size, font_path)` 把它转成了 `(size, font_path)`。插件代码请统一使用后者。

### 图片资源

- `get_image(image_path)`：实时解码为 **RGBA** 图片，**不进缓存**；失败返回 `None`。
- `get_indexed_image(image_path)`：实时解码并**保留原始模式**（通常是 `'P'` 调色板），调用方可用 `pix[x, y]` 直接与索引值比较。它同样是**共享/只读语义**，**调用方禁止原地修改**返回的图对象。

```python
from modules.cache.cache import get_image, get_indexed_image

bg = get_image(path)              # RGBA
sprite = get_indexed_image(path)  # 保留 'P' 模式索引语义，只读
```

### 位图插入与图标

- **位图插入必须使用 Floyd-Steinberg 抖动**，再贴到画布上：

  ```python
  from PIL import Image

  sprite = get_image(sprite_path)
  # 映射到画布调色板时必须开启 Floyd-Steinberg 抖动
  sprite = sprite.convert('RGB').quantize(
      palette=palette_img, dither=Image.Dither.FLOYDSTEINBERG)
  img.paste(sprite, (x, y))
  ```

- **图标优先使用字体图标**（例如用 `weather-icon.ttf` 这类字体直接绘制），不要优先用位图。
- **只有确认文件真实存在时才引用字体**，不要凭空编造文件名。

## 10. 参数校验与错误处理

### 按参数类型的必需参数

| 类型 | 必需参数 | 说明 |
| :--- | :--- | :--- |
| 地理位置类 | `lat`, `lon`, `tz` | 由插件自约定（建议任一出现则三者都要齐），**框架不校验** |
| 用户标识类 | `username` | 在路由层或 lib 层校验非空 |
| 内容选择类 | 无 | 直接透传给上游 API |
| 资源文件类 | `json_name` | 它是路径段 `/{plugin}/json/{name}`，取自 `json_module/` 下 `.py` 文件名；不存在的名字不会命中路由（FastAPI 默认 404），模块导入失败或未实现 `to_json` 抛 `ParamError`(400) |
| 纯内容类 | 无 | 不做额外参数校验 |

补一条视图路由的通用要求：`size` 是必需的，缺失时框架自己会抛 `ParamError('缺少 size 参数')`。

### 错误统一格式

全站错误响应体只有一种形状，由 `modules/errors/errors.py` 的 `error_response()` 产出：

```json
{ "success": false, "message": "错误说明", "code": 400 }
```

在插件代码里，直接抛出框架的异常类即可，异常处理器会把它转成上面的 JSON：

- `ParamError` → 400（参数非法）
- `NotFoundError` → 404（插件自己的资源文件不存在等；框架自身不抛，是留给插件用的）
- `AccessDeniedError` → 403（权限不足）
- `AuthError` → 401（未认证）

```python
import os
from modules.errors.errors import NotFoundError, ParamError

path = os.path.join(plugin_dir, "assets", "data", f"{res_name}.json")
if not os.path.isfile(path):
    raise NotFoundError(f"资源文件不存在: {res_name}")

if not username:
    raise ParamError("username 不能为空")
```

框架在视图端点里会做一层兜底：任何未被识别的异常会被包成 `ParamError('图片生成失败: ...')`；但 `ParamError` 与 `AccessDeniedError` 会**原样上抛**，不会被 400 覆盖，这样调用方才能拿到“权限不足”的语义。

### 日志

**禁止使用 `app.logger.exception()`**。需要打印异常时用 `print()` 或 `traceback.print_exc()`：

```python
import traceback

try:
    data = await fetch_metrics(city)
except Exception:
    traceback.print_exc()
    raise ParamError("上游数据获取失败")
```

## 11. 热重载与调试

### 热重载覆盖范围

- **`plugins/**` 的代码改动可以热重载生效**：视图与 JSON 模块是在**请求时**才 `importlib.import_module()` 的，清掉模块缓存后下一次请求就会执行磁盘上的新代码；`routes.py` 靠热重载重建路由。
- **`modules/**` 等框架代码改动必须重启进程**，热重载不会清理它们。

### 触发方式

- 管理面板插件页的「热重载」按钮。
- 或直接调管理 API：

  ```bash
  curl -X POST http://127.0.0.1:5000/admin/api/plugins/reload
  ```

  返回 `{success, total, loaded, failed, failures}`。

热重载内部（`modules/plugins/plugin_loader.py` 的 `reload_plugins`）会：按身份摘除旧路由 → 清掉 `sys.modules` 里的 `plugins.*` → `clear_plugin_config_cache()` → 重新扫描注册 → **保留已注册插件的开关状态** → 移除已删除插件目录的残留条目 → 置 `app.openapi_schema = None`。

### 加载失败如何定位

插件导入失败时，它**不会出现在 `plugins` 列表里**，只会被计入 `failed`。失败原因会被写进 `plugin_result['failures']`（形如 `{'name': ..., 'error': ...}`），管理面板插件页会展示。所以“少了一个插件”时，先看 `failures`。

### 常见错误对照表

遇到问题先在这张表里对号入座。所有报错文案都取自仓库代码原文：

| 症状 | 大概率原因 | 怎么办 |
| :--- | :--- | :--- |
| 面板插件列表里没有新插件 | 插件导入失败——它不会进 `loaded`，只计入 `failed` | 到面板插件页看 `failures` 里的 `error`；最常见的是 `plugin.json` 的 `name` 与目录名不一致 |
| `/新插件/view/summary?size=hxl` 返回 **404**，但 `/plugin_template/view/summary?size=hxl` 照旧出图，且面板里能看到新插件 | 复制模板后漏改 `routes.py` 的 `PLUGIN_NAME`，路由仍挂在模板名下 | 见 [1.3 改名](#13-改名三处必须一起改最容易漏的一步) |
| 400「视图 xxx.view.yyy 不存在: …」，报错里出现的是**模板名** | 把 `plugin_template/` 目录改名后 `PLUGIN_NAME` 还是旧值，`importlib` 导不到模块 | 同上 |
| 400「视图 … 未实现 generate_image」 | 尺寸文件里没定义 `generate_image` | 按第 5 节的签名补齐 |
| 400「缺少 size 参数」 | URL 没带 `size` | 补 `?size=hxl` |
| 400「size 参数不合法」 | 取值不像模块名（如 `../hxl`、`_hxl`） | 用 `canvas_factory` 里 `SIZES` 的键 |
| 400「rotate 参数必须为 c / cc / h」等 | URL 显式传的保留参数拼错 | 按 [第 4 节 参数优先级](#4-pluginjson-清单与-plugin_configpy-参数)的取值表改（`rotate=c`、`invert=t`、`cmode=2bw`…） |
| 400「用户组禁止使用rotate参数」 | 该账号所在用户组被禁用了 `rotate` / `invert` / `cmode` | 找管理员在用户组「参数限制」里放开 |
| 400「JSON模块 … 加载失败（或 … 未实现 to_json）」 | `json_module/` 下模块语法错误、缺依赖，或没写 `to_json` | 报错里带完整模块路径，照它定位 |
| 400「图片生成失败: …」 | 视图内部抛了框架没识别的异常 | 看进程控制台的 traceback（框架已 `traceback.print_exc()`） |
| 改了 `plugins/**` 的代码，图没变 | 模块缓存 | 面板点「热重载」，或 `POST /admin/api/plugins/reload` |
| 改了 `modules/**` 的代码，没生效 | 热重载**不覆盖**框架代码 | 重启进程 |
| `format=png` 返回 400 | 默认黑名单拒绝 `png` / `bmp` / `webp` / `tiff` / `gif` | 用 `jpg` / `jpeg` / `array`，或在面板配置里放行 |
| 文字位置画出来了但没有字形 | 字体文件名不存在，回落成了 `ImageFont.load_default()` | 只引用真实存在的字体文件（见第 9 节） |

### 本地调试建议

- 用 `python -B run.py` 启动本地完整版服务（dev 模式跳过鉴权、启用缓存与管理面板）。
- 测试链接必须是**完整 URL**，格式为 `http://127.0.0.1:5000/...`，并且**禁止包含 `palette` 参数**：

  ```text
  http://127.0.0.1:5000/plugin_template/view/summary?size=hxl&a=alpha&b=beta&title=Demo
  http://127.0.0.1:5000/plugin_template/view/detail?size=h2xl&format=jpg
  http://127.0.0.1:5000/plugin_template/json/demojson?a=alpha
  ```

- `format` 支持 `jpg`（默认）/ `png` / `bmp` / `webp` / `tiff` / `gif` / `array`（原始像素数组）；但默认黑名单 `IMAGE_FORMAT_BLACKLIST` 会拒绝 `png` / `bmp` / `webp` / `tiff` / `gif`，默认配置下实际可用的只有 `jpg` / `jpeg` / `array`。
- 管理面板插件页的「快速测试」也能直接跑本服务路由，无需手拼 URL。

## 12. 与预渲染/缓存的配合

框架可开启**定时预渲染**（`config.PRERENDER_ENABLE`），把视图/JSON 产物以“与格式无关的索引图”存库，命中时不再调用 Pillow。写插件时理解以下几点即可，无需自己写缓存逻辑：

- **视图参数默认值变化会影响预渲染缓存键**。缓存键由 `modules/prerender/keying.py` 的 `build_identity()` 用「插件名 + 路由 + 归一化后的最终参数」哈希得到，而参数是 `resolve_view_params()` merge 之后的结果。所以“没传 `city` 但默认 `city=beijing`”与“显式传 `city=beijing`”同键；改了默认值 → 键跟着变 → 老图自然 miss，不需要额外失效逻辑。
- 视图路由的 `rotate` / `invert` / `cmode` / `format` **不进缓存键**，它们命中时按当次请求现场套用，一份产物服务所有旋转角度与输出格式。凭证类参数 `evkey` 也会被剔除。
- **命中时不经过 Pillow，但仍会跑格式与权限校验**：命中路径会重跑 `check_format_allowed(fmt, group_id)` 与 `ensure_format_supported(fmt)`，因为图是之前生成的、组权限可能在那之后被改掉。用户组对 `rotate` / `invert` / `cmode` 的参数权限检查也在命中之前执行。
- **插件被禁用时任务记 `skipped` 且保留缓存**：预渲染调度会跳过被禁用插件/路由的任务（状态 `skipped`），缓存原样保留，重新启用后仍可继续命中。插件目录被删记 `invalid`，任务不自动删除，交给管理员处置。

给插件开发者的推论：**把“取数 + 排版”尽量写成纯函数**，同样的最终参数应得到同样的结果；不要在视图里引入与参数无关的随机/时间漂移（时间请从参数 `tz` 与 `now_in_timezone()` 来），否则会影响缓存复用。

## 13. 开发检查清单

新增插件或改动视图后，逐条自检：

- [ ] 目录结构齐全：`routes.py`、`plugin_config.py`、`lib/`、`view/<kind>/{hxl,h2xl,utils}.py`、`json_module/`；`json_module/` / `page/` / `plugin.json` 按需，用不到就不建（三个 `register_*` 遇到不存在的目录直接返回）
- [ ] **三处名字一致**：插件目录名 = `routes.py` 的 `PLUGIN_NAME` = `plugin.json` 的 `name`（漏改 `PLUGIN_NAME` 会让路由停在模板名下，请求新路径只会 404）
- [ ] `plugins/**/__init__.py` 只放 docstring（或为空）；`modules/**/__init__.py` 保持空文件
- [ ] `routes.py` 暴露了 `router = APIRouter()`，且只做路由装配
- [ ] 元信息（版本、描述、作者、最低框架版本、依赖）只写在 `plugin.json`，未写进 `plugin_config.py`
- [ ] 新增的配置项已在 `CONFIG_LABELS` 里登记可读名称（面板不显示大写常量名）
- [ ] 路径全部用 `os.path.join(os.path.dirname(__file__), ...)`
- [ ] 参数优先级正确：URL > `plugin_config.py` > `config.py`；未在导入期捕获任何配置值
- [ ] `DEFAULT_ARGS` 经 `get_plugin_default_args()` 取，非字典按空字典处理
- [ ] 视图**先取数据、再创建画布**
- [ ] `hxl` 与 `h2xl` **都已实现**，且 `h2xl` 是独立布局、未缩放 `hxl`
- [ ] 文本测量全部使用 `draw.textbbox()`
- [ ] 任何元素绘制前都做了边界检查，无越界硬画
- [ ] 字号是 16 的整数倍；核心数值 32px 以上、次要信息 16px
- [ ] 黑色显式写 `fill=1` 或 `fill=(0,0,0)`，未使用 `fill=0`
- [ ] 红色只用于标题/警示/核心数据
- [ ] 网络请求使用 `httpx.AsyncClient` 且设置了 `timeout`；`generate_image` 为 `async def`
- [ ] 时间相关操作使用 `modules/utils/timezone.py` 的函数
- [ ] 字体只从项目根 `assets/fonts/` 或插件 `assets/fonts/` 读取，并走 `get_font()`；只引用真实存在的文件名
- [ ] 位图插入使用 Floyd-Steinberg 抖动；图标优先用字体图标
- [ ] 用到 `json_module/` 时，每个模块都实现了 `to_json(**kwargs)`，返回值能被 `JSONResponse` 序列化
- [ ] 用到 `page/` 时，页面不依赖服务端模板渲染（`page/` 是 `FileResponse` 静态直出，要动态内容就让 JS 调本插件的 JSON 路由）
- [ ] 参数校验符合参数类型表（`lat`/`lon`/`tz` 由插件自约定、框架不校验；`username` 非空；`json_name` 由目录扫描生成，导入失败或未实现 `to_json` 抛 `ParamError`（400））
- [ ] 错误统一走框架异常类，响应体为 `{success, message, code}`
- [ ] 无 `app.logger.exception()` 调用（改用 `print()` / `traceback.print_exc()`）
- [ ] 路由、参数、视图、插件 README 已同步更新
- [ ] 测试链接是完整 URL `http://127.0.0.1:5000/...`，且不含 `palette` 参数
- [ ] 新增/改动逻辑已跑 `python -B -m unittest discover -s .trae/tests`（仅标准库 unittest，不污染 `data/einkviews.db`）
