## 开始使用

### 打开登录页

管理面板与个人控制台都在同一个入口下，本地自建服务默认监听 `127.0.0.1:5000`：

```text
http://127.0.0.1:5000/admin/login
```

登录表单只有「用户名」「密码」两个输入框和「登录」按钮，页面底部有「注册新账号」与「**忘记密码**」两个链接（前者在管理员关闭自助注册时会被隐藏，「忘记密码」始终可用）。点击登录后请求 `POST /admin/api/auth/login`，成功则跳转到 `/admin`。**「用户名」可以填账号名，也可以填账号的 UID**（注册顺序号，见「用户 → 账号」一节的「账号 UID」）；纯数字一律按 UID 解释，所以账号名不允许是纯数字。**账号名不区分大小写**：`Admin` 与 `admin` 是同一个账号，登录、查重、改名都按同一口径，因此不可能同时存在两个只有大小写不同的账号。密码框右侧有「显示 / 隐藏」切换，登录、注册、首次改密与个人控制台的改密处都有。

注意：登录页与 `/admin` 只在 `run.py` 启动的本地链路（dev / prod）中存在。Vercel 是纯 Serverless 部署，没有数据库与持久存储，因此**没有管理面板，也没有 `/admin/login`**。

### 首次登录强制改密

管理员新建账号或被重置密码后，账号带 `must_change_password` 标记。此时访问 `/admin` 不会进入面板，而是显示「首次登录」页：

- 标题：首次登录
- 说明：安全要求：请立即修改默认密码
- 输入：新密码（至少 6 位）、确认新密码

两次输入不一致或长度不足会直接在前端拦截，提交成功后自动跳回 `/admin`。改密只在下次登录使用新密码，当前会话不受影响。

### 注册新账号

注册页 `/admin/register`（页内即 `http://127.0.0.1:5000/admin/register`）包含：

- 用户名、**邮箱（必填）**、密码、确认密码、激活码（选填）

规则：

- 用户名重复返回「用户名已存在」；密码至少 6 位；用户名不能是纯数字（纯数字一律解释为 UID，见上一节）；**邮箱必填**且必须含 `@`，缺失或格式不对返回 400「请输入有效的邮箱」。
- **邮箱的用途只有一个：忘记密码时的凭据**（见下一节）。它**不展示在账号列表里**，只有点开该账号的「详情」弹窗才能看到，账号名 + 邮箱一起匹配才允许改密。
- **填写了激活码**时，落组、账号有效期、到期回落组全部以该码为准（详见[激活码](#激活码)）；无效、已过期或已用尽的码返回 400「激活码无效、已过期或已用尽」。
- **不填激活码**时，账号进入**默认注册用户组**——在管理面板「用户 → 用户组」列表点「设为默认」即可切换（底层配置项 `REGISTER_DEFAULT_GROUP_ID`）。未设置时回落到**内置兜底用户组**（按 `builtin=1` 标记找，**不是按组名**，所以把它改名不影响注册落到哪个组）；若该组也不存在，注册流程会现场重建一个，因此不会因为组被删而注册失败。
- 注册是否开放由配置项「允许自助注册」（`EVKEY_REGISTRATION_ENABLED`）控制。关闭后登录页不再显示注册链接，`/admin/register` 也会直接跳回登录页。

新账号落到默认组后，其限额与权限都来自该组；该组默认不设配额（即不限），但受该组的 `max_evkeys` 约束。用激活码注册且该码设了「账号有效期」时，账号到期后会自动转入该码指定的「到期回落组」。

### 忘记密码

登录页底部的「忘记密码」链接指向 `/admin/reset-password`，页面要求填**用户名 + 注册邮箱 + 新密码 + 确认新密码**：

- 用户名与邮箱**都对得上同一个账号**才放行，任一不符返回 400「用户名与注册邮箱不匹配」。两者都不区分大小写。
- **项目没有邮件服务**，不做「发验证码 / 发重置链接」那一套；注册邮箱在这里就是「你是这个账号主人」的凭据。因此邮箱并不要求全局唯一（多个账号可以填同一个邮箱），重置时必须用户名一起匹配——只比邮箱等于谁都能改别人密码。
- 失败同样计入防撞库（独立的 `reset:` 维度，按账号名与来源 IP 分别计数），阈值与登录一致；重置成功后该账号的登录失败计数会一并清零，可以立刻用新密码登录。
- 老账号（升级前建的、邮箱为空）不能用自助找回，需要管理员在「编辑账号」里补上邮箱。
- 这个页面**与注册开关无关**：注册关了，已有账号照样能找回密码。

### 登录防撞库

连续登录失败会被临时锁定，账号与来源 IP **分别计数，任一超阈值即拒绝**（只按账号锁的话，攻击者换 IP 就能绕过；只按 IP 锁的话，分布式撞库又能绕过）。默认阈值与时长：

| 配置项（面板鉴权配置） | 默认值 | 含义 |
| :--- | :--- | :--- |
| 启用登录防撞库 `LOGIN_GUARD_ENABLE` | 开启 | 关掉即完全不锁定 |
| 失败次数阈值 `LOGIN_MAX_FAILS` | 5 | 窗口内连续失败达到该次数即锁定 |
| 失败计数窗口 `LOGIN_WINDOW_SECONDS` | 300 | 只统计该时间窗内的失败 |
| 锁定时长 `LOGIN_LOCK_SECONDS` | 600 | 触发后需等待多久才能再试 |

被锁定时接口返回 429，文案为「失败次数过多，请 N 秒后再试」，并带 `Retry-After` 头。登录成功后该账号/该 IP 的失败记录会被清空。锁定状态只存在进程内存里，**重启服务后归零**——这是刻意的短时保护，不落库以免给攻击者廉价写放大入口。账号维度的计数统一按**小写账号名**归一，换个大小写重试不会另开一份计数（否则改个字母就能绕过锁定）。

上述四项都可以在管理面板「用户 → 鉴权配置」里调整，保存后立即生效。

## 个人控制台

非管理员账号登录后访问 `/admin`（即 `http://127.0.0.1:5000/admin`）看到的是**个人控制台**，而不是管理面板。顶部只有用户名与「退出登录」。页面用的是与管理面板「我的」页**完全相同的一份卡片**（同一份模板与脚本），唯一的差别是个人控制台多一张**站内信**卡片；页头也是同一套：左上角「**我的**」标题 + 一行说明，与管理面板其它分页（如「统计 / 访问趋势、状态码分布与启动历史」）格式一致。依次包含以下卡片：

### 站内信

只有存在可见内容时卡片才出现。展示管理员发布的公告，标题 + 时间 + 正文；**超过 5 条翻页**。

### 账号信息

整页最上方的一张卡片，一行扁平文本展示三项：**用户名**、**用户组**（组名）、**UID**（账号的对外编号，登录时可替代账号名）。页面不再另设页头标题——那样会把账号名与用户组重复显示一遍。UID 在导航栏里不显示，要查就给用户看这张卡。

### 我的额度

卡片说明：实际额度 = 用户组配额 + 管理员发放额；本账号下所有 API Key 共享同一份额度。

上方展示用户组的四项限额：每分钟请求速率、请求配额、evkey 上限、最大并发渲染；下方的「实时用量」每 15 秒刷新一次，显示：

- 本分钟已用（`本分钟已用 / 每分钟上限 次`，上限为 0 即不限时显示「不限」）
- 窗口内已用（长期配额视图）

实时用量是**只读查询**限流器的内存窗口，不消耗任何额度。

### 我的会员

展示当前账号的会员状态与自助激活入口：

- 右上角徽章：`永久有效`、`剩余 N 天`（到期当天显示「今日到期」）、`已过期`。
- 「会员到期」：激活码开通的到期日（`YYYY-MM-DD`），没设有效期则显示「永久有效」。
- 「过期后转入」：到期后自动转入的用户组名；激活码没设回落组时显示「不转移」。
- 底部输入框 + 「激活」按钮：**注册之后也能输入激活码**，效果与注册时填码完全一致——立刻切换到该码指定的用户组、按码里的设置写入到期日与回落组，并核销一次激活码。

不用重新注册就能升级/续期，所以它相当于一张「会员卡」。几点说明：

- 激活失败（码无效、已过期、已用尽）会明确提示，且不会扣减激活码名额；**同一账号重复输入同一张码**默认会提示「该激活码你已经使用过了」，不会被误报成激活成功。若该码由管理员开启了**「允许反复激活」**，则重复输入会成功，到期日在现有到期日上**叠加**（相当于续费）。
- 管理员账号不能自助激活（提示「管理员账号无需激活码」）；激活码对应的用户组是**管理组**时也不允许自助激活——那等于把管理权限交给任何拿到码的人。
- 激活成功后页面会自动刷新用户组、额度与 API Key 信息，新的限额立刻生效（不需要重新登录或重启服务）。
- 激活码**本身**的有效日期属于管理员侧的管控信息，个人控制台不展示。

### 额度记录

只有存在记录时卡片才出现，**8 条一页**。每行：时间、操作（发放 / 重置）、数量、周期、原因。这里只列管理员的人为操作（发放额度、手动重置用量）；到期自动重置不入账，因此不会出现在这里。

### 权限记录

只读卡片，展示本账号会员属性的变动历史（**调整 / 激活 / 到期归位**），每行含时间、操作、变动前后值（用户组名、到期日、回落组）、操作人与原因；前半段是管理员改的，后半段是激活与到期自动归位。**8 条一页**，没有记录时整张卡片隐藏。详见[权限记录](#权限记录)。

### 我的权限

卡片说明：未列出的默认可用。

- 「可访问的插件」以标签形式展示；带删除线（off）的表示该插件已被显式禁用。
- 「已单独配置的路由」只在确实配置过路由级规则时出现。

也就是说权限是**白名单式的排除**：没被列出来的东西默认允许，被显式禁用的才不可用。

### 我的 API Key

卡片说明：设备侧使用 evkey 鉴权，请勿泄露。表格列：Key、说明、状态（启用中 / 已禁用 / 审批中）、创建时间，以及「复制」「启用/禁用」「删除」按钮。顶部小字显示「已持有 N 个（审批中 K 个）/ 上限 M 个」。

**审批中的申请同样会列在表格里**（Key 列显示「待生成」、状态为琥珀色圆点、操作列显示「审批中」），并在 15 秒轮询里自动消失、换成管理员批准后生成的真实 Key——不会出现「提交完回来什么都没看到」的情况。

删除 Key 会二次确认，删除后使用该 Key 的设备将立即失效且不可恢复。

### 申请新的 API Key

输入「用途说明（选填）」后点「生成新 Key」：

- 若管理员开启了「EVKey 申请需审批」，普通用户提交的是**申请**，提示「申请已提交，等待管理员审核」。
- 管理员本人或关闭审批时**直接发放**，并弹窗显示完整 Key（页面关闭后无法再次查看）。

达到 evkey 上限时按钮会禁用，并弹窗说明原因：上限为 0 时提示「当前用户组不允许创建 evkey」；否则提示已持有 / 审批中的数量与上限，需先删除多余的 Key。

### 修改密码

输入新密码（至少 6 位）与确认新密码，点「更新密码」。同样只在下次登录生效。

## 管理面板逐页说明

管理员访问 `/admin` 进入管理面板，顶部导航依次为：概览、插件、用户、测试、日志、缓存、定时、统计、配置、备份、我的。

### 概览

页首「概览 / 服务运行状态与实时指标」，右侧「刷新」。

- 「本次运行时间」大卡 + 运行模式徽章（dev / prod）。
- 指标卡：总请求、今日请求、今日错误率、今日平均耗时、插件数、账号数、evkey 数、缓存命中率。
- **站内信**卡片：说明「发给指定用户组或全体用户；不勾选用户组即全体可见，超过 5 条翻页」。右上「+ 新增站内信」，弹窗里填标题、内容（选填）、可见范围（勾「全体可见」或点名若干用户组）。每条可「删除」。该卡片**可以按管理组关闭**：在用户组编辑里把「站内信」开关关掉后，该管理组进后台就看不到这张卡片，相关接口也会一并拒绝（403）。该开关只作用于管理端的概览页，普通用户的个人控制台站内信不受影响；内置兜底管理组恒为显示。
- **运行信息**卡片：服务版本 · Python 版本、本次启动、首次启动、累计运行（共 N 次启动）、数据库文件大小、磁盘剩余。若数据库被停用（如 Vercel 模式），数据库文件处会显示「当前模式已停用」。
- **系统健康度**卡片：以 100 分为基准，单项异常扣 35、告警扣 15，最终给出评分与等级（≥90 优秀、≥75 良好、≥60 一般、否则异常），并列出异常/告警项名称。

### 插件

页首「插件 / 开关插件与单条路由，调整插件级配置」，右上「热重载」「刷新」。

插件表格列：插件、**版本**、描述、路由数、状态（开关）、操作。版本来自插件目录下的 `plugin.json`；没有清单的插件在版本列显示「未声明清单」，照旧加载。插件数量由部署决定、要一眼看全，**这张表刻意不加分页**（其余会持续增长的列表都是 5 条一页）。

- **插件清单 `plugin.json`**（`plugins/<插件名>/plugin.json`，示例见 `plugins/plugin_template/plugin.json`）：插件元信息的唯一来源，可声明名称、版本、描述、作者、最低框架版本与依赖（其它插件、建议的 Python 包）。带清单的插件按依赖顺序加载；要求的框架版本高于当前、依赖的插件不存在 / 未加载、或存在循环依赖时，该插件会被跳过并在插件页显示原因；清单格式非法、或名称与目录名不一致则加载失败并显示原因。没有清单的插件照旧加载，只标记「未声明清单」；启动摘要里也会报告「其中未声明清单 M 个」。
- 点插件行的**状态开关**即启用/禁用整个插件。
- 点「路由」打开该插件的路由管理弹窗，可逐条开关单条路由，说明「关闭后该路由立即返回不可用」。
- 点「配置」打开插件配置弹窗，逐项编辑插件 `plugin_config.py` 的参数。每项显示的是插件自报的中文名与说明（键名只在悬停提示里），只有插件真值类型的配置项会列出来，元信息（名称、描述）不在此处。布尔参数是开关（翻转后点「保存」或「保存全部」才落库），文本参数是行内输入框，字典 / 数组参数（如 `DEFAULT_ARGS`）行内只显示一段只读预览，点「编辑」打开一个等宽文本框弹窗改 JSON，改完点弹窗里的「保存」立即生效（格式写错会在文本框下方提示具体原因，不发请求）。被改过的项会打上「已修改」徽章并提供「还原」按钮；底部有「保存全部」（只管行内的开关与输入框，字典 / 数组项由自己的保存按钮提交）。
- 右上「热重载」会重新扫描 `plugins/` 目录、重建插件路由并清空插件代码缓存。**改完插件代码（视图/JSON/配置）不必重启服务**；但框架自身的 `modules/**` 改动仍需重启进程。重载瞬间的在途请求可能失败。
- 若某个插件加载失败，表格下方会单独列出「以下插件加载失败，路由未注册」，并给出每个插件的错误原因——失败的插件不在上面的列表里。

### 测试

页首「接口测试 / 在服务端发起真实请求，支持单次、顺序连发与并发压力测试」，右上「清空结果」。

请求配置区：

- **请求路径**：需以 `/` 开头，占位示例 `/插件/类型/视图名`。
- **查询参数**：按 `a=1&b=2` 形式填写。
- **测试模式**：单次请求 / 顺序连发 / 并发压力。
- **请求次数**（1~200，单次模式固定为 1）、**并发数**（1~50，仅并发压力模式可改）。
- 「开始测试」后，下方「请求负载」展示实际发出的 `GET` 地址、查询参数、evkey 与模式；「测试结果」展示请求数、成功/失败、平均耗时、P95 耗时、最快/最慢、平均大小，并逐条列出每次请求的状态码、耗时、大小、时间与内容类型/错误。压测一次可能排出上百条结果，结果表**5 条一页**。

注意：这里发起的是**服务端真实请求**，会进入请求日志，并且会消耗限流与配额额度、占用渲染并发。压测时请留意这些副作用。

页面下半部分还有一张**接口清单**卡片（数据源 `GET /admin/api/api-docs`）：列出当前全部路由——插件视图 / JSON 路由、框架路由与管理接口——包含方法、所属插件、参数位置以及是否需要 evkey，可以直接对照固件里拼的 URL。它是自研页面，专门替代 prod 下被鉴权挡死、浏览器里打不开的 `/docs`。

### 用户

页首「用户 / 用户组、账号、激活码、注册申请与鉴权策略」，下分四个子标签：**用户组 / 账号 / 激活码 / 申请**，下方固定一张**鉴权配置**卡片。

- **用户组**：表格列 ID、名称、**标记**、evkey 上限、最大并发、每分钟速率、请求配额（「标记」列把「内置 / 默认注册组」标记与「管理组 / 普通用户组」类别两组合并到一列，所有圆点列整列居中）；每行「权限」「激活码」「编辑」「删除」，以及「设为默认」（当前默认注册组显示为不可点的「默认组」；两种状态按钮等宽对齐）。右上「+ 新增用户组」。**表格状态列一律只有彩色小圆点**（悬停有说明），含义由卡片标题下的**分行图例**承担——「标记」行 金点=内置兜底组 / 蓝点=默认注册组，「类别」行 紫点=管理组（悬停可看它开放了哪些后台分页）/ 灰点=普通用户组。列表分页 20 条一页，卡片头带「搜索名称 / ID」输入框，按名称或 ID **即时过滤**（只筛当前已加载的列表，输入时自动回到第 1 页）。**兜底管理组（`id=1` admin）整组锁定**：它永远拥有全部权限，行内的「权限」与「编辑」按钮都置灰，删除按钮同样置灰。**管理组（类别为管理组的所有组）的「激活码」与「设为默认」两个按钮也置灰**——后端不允许给管理组生成激活码（拿到码的人等于拿到后台权限），也不允许把管理组设为默认注册组。
  - ID 是数据库真实主键，**删过组后编号不会复用**，所以列表里的 ID 可能不连续（如 1、2、3、5、8），这是正常现象，不代表有数据丢失。（账号列表是唯一的例外，展示的是对外编号 UID，见下面的「账号 UID」。）
- **激活码**：按用户组筛选 + 一个大列表（激活码 / 目标用户组 / 已激活 / 有效日期 / 账号有效期 / 到期回落 / 备注 / 重复激活 / 状态 / 操作），行内可启用·停用、点击「重复激活」列的小圆点切换、删除，右上「+ 生成激活码」可选目标用户组（只列普通用户组）。「重复激活」与「状态」是两组圆点，卡片标题下分两行给出图例：「重复激活」行 蓝点=可重复 / 灰点=仅一次，「状态」行 蓝点=可用 / 灰点=已停用。详见[激活码](#激活码)。分页 20 条一页。
- **账号**：表格列 **UID** / 名称 / 用户组 / evkey 数 / 有效期 / **状态** / 操作；状态列只有圆点（蓝点=启用 / 灰点=禁用），图例在卡片标题下。API Keys、额度、用量三块已合成操作列里的一个「**详情**」按钮，弹窗内用子标签切换；**弹窗里的三张列表各自 5 条一页**（API Keys、按天/按插件用量、额度变动记录），翻页只重画列表、不动弹窗上方填到一半的表单。另有「权限记录」「编辑」「删除」；「权限记录」弹窗里的记录表同样 5 条一页，翻页保留表单内容。**邮箱不占表格列**，只在「详情」弹窗的账号名下方展示（`未设置` 表示老账号尚未补邮箱）。「新增账号」与「编辑」弹窗里都有邮箱输入框（新建必填；编辑留空即清除，仅改其它字段时不会因老账号没邮箱被卡住）。卡片头带**排序下拉**（默认 **UID 升序**，可切按用户组 / 名称 / UID 倒序）与「搜索名称 / UID / 用户组」输入框，即时过滤。可勾选多行做「转移用户组」「批量启用」「批量禁用」「批量删除」。右上「+ 新增账号」。分页 20 条一页。管理组下的账号不参与批量操作，当前登录账号也不能被禁用或删除，**建库时生成的内置管理账号不可删除也不可编辑**（两个按钮都置灰）——改坏它后台就没有兜底的管理入口了。它自己的密码走「我的 → 修改密码」。
- **账号 UID**：每个账号注册时自动分配一个对外编号 `uid`，就是**注册顺序号**，从 `10000` 开始、不设位宽（到 `99999` 之后自然进位成 `100000`）。它是账号在界面上的唯一编号，登录也能直接用它；内部主键 `id` 不再出现在界面上。存量账号按原有顺序从 10000 依次补号，**不会重排**已经发出去的号。账号名**不允许是纯数字**（注册 / 新建账号 / 改名三处都会被拒），以免和 UID 撞车、登录时无法区分；账号名也**不区分大小写**，唯一索引建在 `lower(name)` 上，因此不可能出现两个只有大小写不同的账号。
- **申请**：见 [evkey 的申请与审批链路](#evkey-的申请与审批链路)。
- **鉴权配置**：鉴权开关、白名单、登录防撞库与审批开关等（这些配置按领域归到本页，不在「配置」页出现）。

### 日志

页首「日志 / 请求记录与配置变更审计」，右上切换「请求日志 / 配置审计」两个子标签。

**请求日志**：

- 过滤：全部插件下拉、**全部账号下拉**、全部状态下拉（`4xx+` / `5xx`）、每页 50 / 100 / 200 条。三个筛选条件同时生效。
- 翻页：「上一页」「下一页」；导出「CSV」「JSON」；「清空」需输入确认词。**导出跟随当前筛选**（按账号筛过就只导出该账号的记录），CSV 里多一列「账号ID」。
- 页头统计：`当前页 / 总页数 页 · 共 N 条 · 保留 X 天 · 队列 size / maxsize（已丢弃 N 条）`。
- 表格列：时间、方式、路径、插件、**账号**、状态、耗时、请求 ID、错误。账号列显示账号名而不是数字 id；用环境变量 `EVKEY` 鉴权（没有账号身份）的请求显示 `-`。不记录 evkey。

**日志的双重上限**：请求日志既按「日志保留天数」（`REQUEST_LOG_RETENTION_DAYS`，默认 7 天）按天清理，也按「日志栈深度」（`REQUEST_LOG_MAX_ROWS`，默认 10000，0=不限）限制总条数，超出会淘汰最旧记录。写入是异步队列，队列积压与因溢出被丢弃的条数会直接显示在日志页头部，不再是无声丢日志。

**配置审计**：记录管理接口的写操作——时间、账号（含 `#id`）、来源 IP、方法、路径、状态、详情。可翻页与「清空」。它回答的是「谁在什么时候改了哪个管理接口、结果如何」。

### 缓存

页首「缓存 / 字体与图片资源缓存状态」，右上「刷新」「清除全部」。

- **缓存概览**：说明「进程内字体 LRU 池，不过期，重启后自动重建」。指标：字体缓存条目（`当前 / 上限`）、命中率、命中 / 未命中。
- **缓存配置**：字体缓存池容量（项目约定图片不进池）。

容易误解的一点：这里的**命中/未命中只反映字体文件的加载**。本项目缓存的对象**只有字体**（`ImageFont` 实例，key 形如 `font:路径:字号`），图片由 `get_image()` / `get_indexed_image()` 实时解码，不进池、不计命中。字体池容量由 `CACHE_MAXSIZE` 控制（默认 64），且**不过期**，重启后自动重建。Vercel 模式下缓存被停用，此处会显示「已停用」。

### 统计

页首「统计 / 访问趋势、状态码分布与启动历史」，右上选近 1 / 7 / 30 / 90 天。

- **访问统计**：KPI 为总请求、错误、错误率、平均耗时、单日峰值；「每日请求」柱状图（红底段表示当日错误占比）；「状态码分布」按 2xx/3xx/4xx/5xx 堆叠展示；「请求排行」可切「按插件」「按账号」，**整表列出、5 条一页**（早先只显示前 10 项，现已取消截断）。按插件时点插件行可展开该插件的路由明细（含 p50/p95）。按账号里没有账号身份的请求（用环境变量 `EVKEY` 鉴权）归入「未登录」。

**p50/p95 的口径**：它们基于请求日志，并且**排除了命中预渲染成品缓存的请求**（这类请求约 1 毫秒，与真实渲染混在一起会把分位整体拉低）。要看真实渲染性能，认这一列。

### 配置

页首「全局配置 / 图像、时区、限流、并发等运行参数」，右上「刷新」。配置项按 `category` **分组渲染**，每组一个小组标题并标注项数，顺序为：图像参数、时区、限流、并发、共享存储、管理面板、其他。

已被打散到各自页面的类别**不会**在这里出现：缓存配置在缓存页、鉴权配置在用户页、统计配置在统计页、定时配置在定时页、备份配置在备份页。

每项显示名称、配置 key、当前值与操作入口，控件按值本身的类型走：

- **开关项**（`True` / `False` 的配置，如默认反色、启用鉴权、启用限流）直接显示成开关，**点一下即保存生效**，不用再手打 `true` / `false`。
- **列表项**（鉴权白名单、限流白名单）点「编辑」弹出 JSON 编辑框，内容形如 `["webp","tiff"]`；格式不对会在弹窗里当场提示，不会写进库。
- **取值固定的项直接给候选**：默认输出格式、TIFF 压缩方式、默认旋转角度渲染成**下拉框**（选完即存，和开关一样点一下生效；点开列表时不会误提交，可以慢慢选）；输出格式黑名单渲染成**复选弹窗**（勾选即可，不用记 JSON 数组语法）。候选只列真正支持的取值，不会出现「选了还被拒」的组合。下拉与复选框都统一成面板的扁平外观（选中 = 近黑填充 + 白色对勾），弹窗里堆叠的表单项（以及用户组弹窗里的各项）宽度一致、右边缘对齐。
- 其余数值 / 文本项仍是行内「编辑 → 保存」。

另有三个与配置相关的入口：

- **导出配置 / 导入配置**：页首除「刷新」外还有这两个按钮。导出得到一份可读 JSON（全局配置项 + 插件配置项 + 各用户组限额 / 配额），可跨实例搬配置、可 diff；导入时会校验包结构、只接受本系统认识的配置项，不认识的项与取值非法的项会被跳过 / 拒绝并给出摘要，不会整包失败。它与「备份」分工不同：备份是整库快照、用于回滚，配置导出只含配置、用于迁移与比对。
- **界面语言**（管理面板类别）：`auto`（默认，跟随浏览器语言）/ `zh-CN` / `en` 三档下拉，选完即生效、无需重启。已全量迁移：面板与用户控制台的全部文案（导航与分页名、按钮、提示与空态、分页条、配置项名称与说明、状态圆点图例）、登录 / 注册 / 找回密码 / 首次改密页，以及接口返回的提示信息都随之切换；界面里不再有硬编码中文，新增文案一律加进 `modules/i18n/` 的两份词条表。
- **请求体大小上限**（限流类别）：单个请求体超过上限（默认 8MB）直接返回 413，`0` = 不限；仅本地部署生效（Vercel 由平台自身限制）。「备份上传上限」是更宽松的独立上限（默认 64MB），不受这一项影响。

无论哪种，改完都是**热更新**（通过 `setattr` / 重新加载配置模块生效），无需重启；被覆盖过的项会多出一个「还原」，点它删除该项覆盖、回到代码默认值。

### 备份

页首「备份与恢复 / 导出整库快照，或用备份文件整体替换当前数据库」，右上「刷新」。数据库是整个服务唯一的持久状态（账号、用户组、权限、激活码、日志、统计、预渲染成品都在里面），这一页就是它的导出、整体替换与每日自动备份入口。

- **概览指标**：库大小、已有备份份数、备份占用、上传上限。最近一次备份时间在下方「操作」卡片头右侧（备份是否还在正常产出，看这一行最快）。
- **下载当前备份**：用 SQLite 官方的在线备份接口导出一份**一致性快照**并直接下载，文件名形如 `einkviews-20260925-120000.db`。服务正在写入时导出同样安全（快照会在页被改动时自动重来），不需要停服务。
- **选择文件**：从本机挑一个 `.db` 备份；未选中时右侧「上传并恢复」是禁用的，选中后按钮下方显示文件名与大小。
- **上传并恢复**：选好 `.db` 文件后点「上传并恢复」，先弹二次确认（红色危险样式）。确认后服务端按顺序做四件事：

  1. 校验上传文件：SQLite 魔数、能否打开、`PRAGMA integrity_check` 必须为 `ok`、必须含 `user_groups` 与 `accounts` 两张表；超过「备份上传上限」直接拒绝（请求头带 `Content-Length` 时**先看长度再读 body**，不必等整个文件进内存）。
  2. 把**当前库**自动备份到 `backups/einkviews-auto-<时间戳>.db`（后悔药；这一步失败会中止恢复）。
  3. 替换数据库文件并重建连接。
  4. 重新加载全部内存态：权限缓存、插件/路由开关、配置覆盖、统计基线、组限额、鉴权缓存、限流与防撞库计数、内存成品缓存、预渲染调度。

  恢复成功后**所有登录态立即失效**，面板自动跳回登录页，需要用恢复出来的账号重新登录。
- **备份文件**：列出 `data/backups/` 里的自动快照（文件名、大小、时间，超过 10 份翻页），行内三个操作：**「下载」**把这一份存到本机、**「恢复」**直接用它整体替换当前库（等价于「先下载再上传」但省掉这一步，确认弹窗与上传恢复同一套；恢复完这份快照仍留在原地，可以反复使用）、**「删除」**逐份清掉。这个目录**只进不出**——每次恢复前都会在这里留一份后悔药，没有别的入口删它，所以卡片右上还有一个「按保留策略清理」，按下面的保留份数 / 保留天数一次删掉超出的（后台每轮也会自动兜底清一次）。
- **保留策略**：`BACKUP_KEEP_COUNT`（最多留几份，默认 30）与 `BACKUP_KEEP_DAYS`（超过多少天自动删，默认 0）；**任一为 0 表示该维度不限**，两个都设了就是「超出任一即删」。管理员自己归档的备份是从浏览器**下载到本机**的，不经过这个目录，不会被清理波及。
- **自动备份**：打开「启用自动备份」并在「自动备份时刻」填 `HH:MM`（空格或逗号分隔可写多个，如 `03:30 15:00`，按面板时区解释），服务每天在这些时刻做一份整库快照落到 `data/backups/`。它与恢复前自动留的「后悔药」是同一目录，共用上面的保留策略（面板上的「导出数据库」是下载到本机的一次性导出，不落在该目录）；多实例部署只有 leader 实例执行，不会重复备份。

> 恢复是**不可逆的整体替换**：目标文件里没有的账号、权限、配置就是没有了。想留住当前状态，先点「下载当前备份」。

**备份配置**卡片含：`BACKUP_UPLOAD_MAX_MB`（上传上限，默认 64 MB，取值 `0` = 不限，不建议——整库会被读进内存做校验再落盘，一个超大文件就能把进程内存吃掉）、`BACKUP_KEEP_COUNT`（备份保留份数，默认 30）、`BACKUP_KEEP_DAYS`（备份保留天数，默认 0）、`BACKUP_AUTO_ENABLE`（启用自动备份，默认关闭）与 `BACKUP_AUTO_TIMES`（自动备份时刻，`HH:MM`，空格或逗号分隔可写多个，按面板时区解释）。`BACKUP_KEEP_COUNT` 与 `BACKUP_KEEP_DAYS` 都是 `0` = 不限。

> 无数据库的模式（Vercel）这一页整体不可用，接口直接返回「当前运行模式未启用数据库」。

### 我的

个人页（管理组与普通用户都有；普通用户看到的完整版是[个人控制台](#个人控制台)，管理组在这里看到的是同一套账号侧信息），左上角是与其余分页同一套的页头「**我的** / 账号信息、额度与会员、API Key 与登录密码」。

- **账号信息**：一行扁平文本，用户名、用户组、UID 三项（页头不重复这三个值）。
- **我的额度 / 我的会员**：卡片清单见[个人控制台](#个人控制台)对应小节，管理组在这里看到的是同一套卡片（少一张站内信）。
- **权限记录**：只读卡片，本人用户组升降、会员到期日增减与到期回落的变动记录（含操作人与原因），**8 条一页**；无记录时整张卡片隐藏。
- **修改密码**：新密码至少 6 位；两个密码框右侧是眼睛图标，点击切换明文/掩码。
- **我的 API Key**：列表可「复制」「启用/禁用」「删除」；提交的申请在列表里以「待生成 / 审批中」（琥珀圆点）占位，管理员在这里建 Key 不需要自己审批，直接发放。Key 会越攒越多，列表**5 条一页**分页。

## 用户组、账号与权限

### 用户组字段

在「用户 → 用户组 → 新增/编辑用户组」弹窗里可以设置以下字段：

| 字段 | 面板标签 | 语义 |
| :--- | :--- | :--- |
| `category` | 用户组类别 | `admin` = 管理组（能进后台），`user` = 普通用户组（只有个人控制台），见[用户组类别](#用户组类别) |
| `admin_tabs` | 可访问的后台分页（类别选管理组时才出现） | 多选该管理组能操作哪些后台分页，空 = 只有「我的」 |
| `show_announcement` | 站内信（类别选管理组时才出现） | 该管理组能否看到概览页的站内信卡片，默认开；关掉后卡片隐藏且相关接口返回 403，只影响管理端概览页 |
| `max_evkeys` | evkey 上限（-1 = 不限，0 = 禁止创建，N = 最多 N 个） | **三态**，见下文 |
| `max_concurrent_renders` | 最大并发渲染（0 = 不限，按账号独立计数，优先级高于全局配置） | 0 = 不限；用户组的值优先于全局 `MAX_CONCURRENT_RENDERS` |
| `rate_limit_per_minute` | 每分钟请求速率（0 = 不限，按账号独立计数） | 0 = 不限 |
| `quota_limit` | 请求配额上限（0 = 不限，按账号独立计数，同账号下所有 evkey 共用） | 0 = 不限 |
| `quota_period` | 配额模式 | 见下文 |

> `max_evkeys` 与 `max_concurrent_renders` 对**管理组**（`category = admin`）一律按「不限」执行：服务端把这两项折算成不限（evkey 记作 `-1`、并发记作 `0`），组编辑弹窗里它们对管理组是禁用状态并附一行说明，用户组表格的两列与「我的」页显示的也都是「不限」。库里存的那份数值对管理组不生效，也不会因为编辑一次就被改写。

### 用户组类别

每个用户组有一个**类别**，决定这个组的人登录后能进哪里：

- **管理组（`category = admin`）**：能进后台，且在后台里能看到哪些分页由该组勾选的「可访问的后台分页」决定（可多选）。「我的」分页任何身份都有、不参与勾选。
- **普通用户组（`category = user`）**：登录后只有个人控制台，看不到后台。

**组名（`admin` / `Free`）只是显示名**，不代表权限；真实类别只在管理面板的用户组列表的「标记」列里可见（该列把「内置 / 默认注册组」标记与类别合并展示：紫点 = 管理组 / 灰点 = 普通用户组，悬停管理组可看它开放了哪些分页）。用户组的表格状态列一律只有彩色小圆点，含义由卡片标题下的**分行图例**承担：「标记」行 金点 = 内置兜底组、蓝点 = 默认注册组，「类别」行 紫点 = 管理组、灰点 = 普通用户组，每个圆点悬停都有说明。管理组同样有「我的」分页与权限记录；概览页的站内信卡片还能按组单独关闭（`show_announcement`）。

### 「0 = 不限」这条约定，以及唯一的例外

项目通用约定是 **数值型上限填 `0` 即不限**：

- `rate_limit_per_minute = 0`：不限速。
- `quota_limit = 0`：不限配额（热路径上完全不碰数据库，零开销）。
- `max_concurrent_renders = 0`：不限并发（内部用一个极大信号量代表无限）。
- 定时任务的「缓存寿命 `0`」：不因空闲过期。
- 「日志栈深度 `0`」：不限制总条数。

**唯一的例外是 `max_evkeys`**：它是三态，`0` 表示**禁止创建**而不是不限。判断 evkey 能不能创建时务必按这三态来理解：

| 取值 | 含义 |
| :--- | :--- |
| `-1` | 不限数量 |
| `0` | 该用户组**禁止创建** evkey |
| `N > 0` | 最多 N 个 |

另外要注意：**审批中的申请同样占名额**（否则用户能把申请堆到上限之外），且**禁用某个 evkey 不会释放名额**（名额按已持有数量算，与启用状态无关）。

### 配额周期：两种模式

`quota_limit` 必须配合 `quota_period` 理解。面板编辑弹窗用两个 optgroup 明确区分这两类模式：

- **按时间周期（到期自动重置）**：`day` / `week` / `month` / `year`。到期后 `used` 归零，**未用部分不结转（额度不累加）**，每期固定就是配额值。周按 ISO 周历计算。
- **按次总量（该账号一共就这么多，用完即止）**：`trial`。**永不重置**，用完为止。内置 `Try` 试用组默认就是这一模式。

**非法值一律回落 `day`**（`normalize_period()`）。两种模式对所有用户组都可用、可自由切换；它**只作用于配额**，evkey 上限 / 并发 / 速率不受影响。

### 权限写入语义

- **未显式配置 = 默认允许**。新用户组不需要逐个去开权限。
- 只有**显式写入 `false` 才是「禁用」**，`true` 是「允许」。
- 传 **`null` 表示删除规则、恢复默认允许**。

接口层面：`POST /admin/api/groups/{id}/permissions` 的 body 为 `{"plugins": {"插件名": true/false/null}, "routes": {"路径": true/false/null}}`；参数限制接口 `POST /admin/api/groups/{id}/params` 的 body 为 `{param_key, enabled}`（单个）。

**不要用「删除规则」来表达禁用**——删除规则等于恢复默认允许，会导致怎么禁都禁不掉。因此在权限弹窗里：

- 点插件或路由的开关 = 写入显式 `true`/`false`。
- 点参数标签 = 已禁止时传 `null`（恢复默认允许），未禁止时传 `false`（写入显式禁用）。

### 参数限制

在权限弹窗下半部分可以按用户组禁用特定参数。内置可快速切换的常见参数：BMP、PNG、JPG、WebP、TIFF、GIF、Raw数组、旋转、反色、色彩模式；也可以「自定义参数名」后点「添加禁止」。某参数被禁用后，该组请求带上这个参数会被拒绝（例如「用户组禁止使用 rotate 参数」）。

### 内置组与删除行为

系统内置**两个兜底组**：一个兜底管理组（`id=1` admin）与一个兜底用户组（`id=2` Free），它们**不可删除**，且**类别与可访问分页固定不可改写**（名称与限额仍可改）——改掉内置管理组的类别会让所有人同时失去后台入口。内置 `Try` 试用组是普通可删的组。

**组名随时可改，改它不影响任何数据**：激活码、会员到期回落、账号归属、插件 / 路由 / 参数权限全部按 `group_id` 关联，类别判定也只看 `category`——把某个组改名成 `admin` 不会让它变成管理组，把内置 `Free` 改名也不会让注册落到别处（回落认的是 `builtin` 标记，不是组名）。

**兜底管理组还额外整组锁定**：它永远拥有全部权限，所以行内的「权限」与「编辑」按钮都置灰，接口也一律拒绝。它自己也**不受任何插件 / 路由 / 参数限制**（库里即使留着旧规则也一律忽略）——否则管理员在这里给自己配一条禁用规则，整个后台就当场锁死，而且没有界面还能改回来。内置 `Free` 兜底用户组不受此限制，照常可编辑。

删除一个用户组要同时满足三条：

1. **内置组不可删**：删除按钮直接禁用并给出提示。
2. **组内还有「激活码开通且未到期」的账号时不可删**：这类账号是花激活码换来的限期权限，删组等于单方面终止已售出的时长，删除按钮禁用、提示会带上这类账号的数量。判定看的是该账号**最近一条**会员变动记录是否为「激活码开通」，所以**管理员手动提级 / 手动建号进来的账号不算**（那本就是管理员自己的操作），激活之后又被管理员手动改过用户组或到期日的也不再算。
3. **删掉的若正好是默认注册组**，这个标记随本次删除的落点走：选择「转移账号」→ 标记跟着转到目标组；选择「连同账号一起删除」→ 标记落到内置兜底用户组。目标组是管理组时不会继承这个标记。

满足条件后删除时，弹窗会让你二选一：把组下账号「转移到其他用户组」，或「连同账号一起删除」；还要输入组名二次确认。

- 删除用户组不可恢复，其权限配置与参数限制会一并删除；该组名下的**激活码会一并清理**，指向它的账号「到期回落组」会被归零（避免残留引用撞外键导致注册或到期扫描失败）。
- **管理组不接受批量转入**（删除时的「转移到」下拉里不出现管理组，接口也直接拒绝）——那等于批量授予管理权限，只能逐个在账号的「权限记录」弹窗里调整。

### 默认注册组

「用户 → 用户组」列表里每行都有两个入口：

- **设为默认**：把该组设为自助注册的默认落组（写配置项 `REGISTER_DEFAULT_GROUP_ID`）。当前默认组在名称列带**绿色小圆点**（悬停提示「默认注册组」），该行按钮变为不可点的「默认组」。**管理组不能设为默认注册组**，按钮置灰并提示。
- **激活码**：跳到「用户 → 激活码」标签页并自动筛出该组的激活码（见[激活码](#激活码)）。

修改入口就是上面的「设为默认」按钮（底层写配置项 `REGISTER_DEFAULT_GROUP_ID`，`0` = 内置兜底用户组）；鉴权配置整体在用户页，不会在「配置」页出现。配的组被删除时自动回落到内置兜底用户组，它也不存在时注册流程会现场重建，不会因为组被删而没人注册得进来。

### 激活码

激活码从属于某个用户组，注册时填入即进入该组。管理入口是「用户 → **激活码**」标签页（与用户组卡片平齐的独立区块），不再挂在用户组弹窗里：

- 右上「**+ 生成激活码**」：首项就是**目标用户组**下拉，选好组再设可激活账号数、有效日期、账号有效期、到期回落组与「允许同一账号反复激活」勾选框。
- 顶部**用户组筛选**下拉：按组筛选（例如只看 `Pro` 组的码），此时列表下方的操作只作用于筛出来的码。
- **大列表**逐行展示：激活码 / 目标用户组 / 已激活（`已用 / 上限`）/ 有效日期 / 账号有效期 / 到期回落 / 备注 / 重复激活 / 状态 / 操作，行内即可**启用·停用**、点击「重复激活」列的圆点切换该开关、以及**删除**。

生成时可设置：

| 字段 | 语义 | 留空 / `0` 的含义 |
| :--- | :--- | :--- |
| 可激活账号数 `max_uses` | 最多能激活几个账号 | `0` = 不限 |
| 有效日期 `expires_on` | 激活码自身的失效日期（`YYYY-MM-DD`，过了当天即失效） | 留空 = 码永不过期 |
| 账号有效期 `duration_days` | 激活出的账号能存活多少天（自激活当日起算） | `0` = 永久有效 |
| 到期回落组 `fallback_group_id` | 账号到期后自动转入的用户组 | 留空 = 不转移（仅标记已过期） |
| 允许反复激活 `allow_repeat` | 同一账号能否反复激活这张码（续期语义） | 不勾选 = 同一账号只能激活一次 |
| 备注 `note` | 便于管理员分辨用途 | 可选 |

状态以**彩色小圆点**展示（卡片标题下分行图例：状态行 蓝点=可用 / 灰点=已停用；「重复激活」行 蓝点=可重复 / 灰点=仅一次），可用的判定与核销条件共用同一套逻辑，不会出现「面板显示可用、注册却被拒」。

**生命周期**（一张码从生到死的全过程）：

1. **生成**：选定目标用户组与上面各项参数，码为随机十六进制串。
2. **核销**：注册页填入，或登录后在个人控制台「我的会员」输入 → 立刻切到该码指定的用户组，按码里的设置写入到期日与回落组。
3. **销毁**：
   - **用完即销毁**：有限次（`max_uses > 0`）的码在最后一次核销后**立即从列表消失**，不留历史记录；`max_uses = 0` 的码永不销毁。
   - **过期即销毁**：过了「有效日期」的码同样当场清理，列表读之前也会先清一遍（后台扫描周期是分钟级，不靠它兜底）。
   - 删除激活码、删除用户组都会连带清掉该码的核销记录。

规则与注意点：

- **同一账号对同一张码只能生效一次**（默认）：重复输入会明确提示「该激活码你已经使用过了」，不会再报一次激活成功，到期日也不会被重复顺延（`max_uses = 0` 的码也一样）。其他人用同一张码仍正常。生成时勾选**「允许同一账号反复激活」**即可解除这一限制，开关状态在列表里以「重复激活」列的彩色圆点展示（点击即切换）。
- **开启「允许反复激活」后**为**续期语义**：同一账号可以反复输入这张码，新的到期日**在现有到期日上叠加**（未用完的天数不丢；已过期则从今天起算；账号当前是永久、或首次被限期码激活，也都从今天起算）。注意**每次激活照常占一个可激活账号名额**——所以 `max_uses > 0` 的码会被一个账号自己用光并立即销毁，想当「续费码」用请把可激活账号数设为 `0`（不限）。另外开启期间的激活**不写核销记录**，因此**把开关关回去之后，该账号最多还能再激活一次**（无从追溯它此前用过几次）。
- 上限判定与次数自增在同一条原子 SQL 内完成，多人同时注册也不会超发。
- 核销之后若建号 / 落组失败（例如用户名刚被别人抢注、码指向的组已被删），名额会**自动归还**且不留核销记录，不会白扣一次、也不会把账号永久标记成「已用过」。
- 停用后立刻不可用，随时可以再启用；已激活的账号不受影响。
- 账号到期归位由「启动时扫一次 + 后台刷盘线程周期性扫描」自动完成，**不需要定时任务**；归位后清空到期日与回落组，账号永久归属新组。
- 账号列表有**「有效期」**列，可直接看到激活码开通的账号何时到期（永久有效显示 `—`）。
- **注册之后也能用**：用户在个人控制台「我的会员」卡片里输入激活码即可自助升级/续期（详见[我的会员](#我的会员)），不必重新注册。
- **管理组（类别为 `admin` 的组）不参与激活体系的任何一环**（判定按类别而非组名）：既不能作为码的目标组，也不能作为到期回落组或批量转移的目标组，生成入口与注册、自助激活两条核销路径都直接拒绝（那等于把管理权限交给任何拿到码的人）。

管理端接口：

| 方法 | 路径 | 用途 |
| :--- | :--- | :--- |
| GET | `/admin/api/activation-codes` | 列出激活码（`?group_id=` 按组筛选、`?status=` 按状态筛选），每行带目标组名与状态 |
| POST | `/admin/api/activation-codes` | 新建激活码（body 带 `group_id`），返回 `code` |
| PUT | `/admin/api/activation-codes/{code_id}` | 启用 / 停用（body `{enabled}`）、切换「允许反复激活」（body `{allow_repeat}`）；**只修改请求体里出现过的字段** |
| DELETE | `/admin/api/activation-codes/{code_id}` | 删除（连带清理核销记录） |

用户端接口：

| 方法 | 路径 | 用途 |
| :--- | :--- | :--- |
| POST | `/admin/api/my/activation` | 自助核销激活码（body：`{code}`），落组 / 到期日 / 回落组以码为准 |

注册接口 `POST /admin/api/auth/register` 的请求体为 `{username, email, password, code}`：`code` 选填，`email` **必填**（项目不发邮件，它只作找回凭据）。找回接口 `POST /admin/api/auth/reset-password`（body：`{username, email, password}`）——用户名与注册邮箱**同时匹配**才当日改密，因此**无需登录态**（与注册、登录同属免鉴权前缀），失败按 `reset:` 维度计入防撞库。

### 权限记录

会员属性的每一次变动都有记录，管理端与用户端都能查：

- **改动入口**：面板「用户 → 账号」列表每行的「**权限记录**」按钮，弹窗里可改三项——**用户组**、**到期日**（`YYYY-MM-DD`，留空 = 永久有效；也可以理解为「提前结束」或「延长会员时长」）、**到期回落组**（`0` = 不转移，留在原组），并可以填「原因」。保存后立即生效（用户组权限缓存与该组的并发信号量会一并失效，不用重启）。
- **记录内容**：每行展示时间、操作类型（**调整 / 激活 / 到期归位**）、变动前后值（用户组名、到期日、回落组）、操作人与原因。只有真正发生变化的字段才会记一条，没变就不写。
- **四类来源**：
  - `set` —— 管理端调整会员属性（含批量转移用户组）；
  - `activate` —— 注册时用激活码开通，或登录后自助激活；
  - `expire` —— 账号到期后自动归位到「到期回落组」（归位后清空到期日与回落组）。
- **管理端**：`GET /admin/api/accounts/{id}/membership-logs?limit=100`（配合 `PUT /admin/api/accounts/{id}` 改会员属性）。
- **用户端**（只读）：`GET /admin/api/my/membership-logs`，个人控制台的「权限记录」卡片按 8 条一页展示；没有记录时整张卡片隐藏。面板「我的」分页也有一张同名卡片，管理组同样能看到自己的升降记录。

## 配额的使用与运维

### 计数范围是账号

配额与速率都**按账号独立计数**：同一个账号下的所有 evkey **共用同一份额度**；不同账号互不影响。用户组只提供额度的**数值**与权限，不参与计数。

### 实际额度

```text
实际额度 = 用户组配额（quota_limit） + 管理员为该账号发放的累计额度（granted）
```

用户组配额为 0（不限）时不存在「实际额度」的概念，发放也没有意义。

### 发放额度（面板「额度」按钮）

在「用户 → 账号」列表，点某账号的**「额度」**按钮打开弹窗。弹窗顶部四个指标：实际额度、本周期已用、剩余、累计发放；下方依次是：

- **发放额度**：一键 `+500` / `+1000` / `+2000`，或「自定义次数（负数=回收）」后点「发放」；可填「原因（选填）」。
- **重置本周期已用**：填原因（选填）后点「手动重置」。
- **变动记录**：时间、操作、数量、周期、原因、操作人。

发放规则：

- 正数为发放、**负数为回收**。
- 调整后**总额度必须 ≥ 1 次**，否则返回「调整后总额度需至少为 1 次」（0 在本项目等于不限、负数则永远放行不了，都会静默走样，所以直接拒绝）。
- 发放数量不能为 0。
- 用户组配额为 0（不限）时拒绝发放，提示「该账号所属用户组未设置配额（不限），无需发放」，弹窗内相关按钮也是禁用的。
- 发放额记在账号上、**跨周期持久保留**，不随周期重置归零。

### 手动重置 vs 自动重置

- **手动重置**（面板「手动重置」/ `POST /admin/api/accounts/{id}/quota/reset`）：只把**本周期已用**（`used`）归零，**不动已发放的额度**。
- **到期自动重置**：`day/week/month/year` 到点后 `used` 归零、未用不结转。它由下一次请求**惰性触发**（发现周期起点变了就当场归零），不依赖定时任务，所以停机再久重启后也能自动进入新周期，且停机期间的时间不会被算进额度。
- `trial` 永不自动重置。

### 流水记录

- **人为操作**（发放 / 手动重置）写入 `account_quota_logs`，可在**管理端额度弹窗**与**用户控制台「额度记录」**两处查看。
- **到期自动重置不写流水**——否则每个周期的首个请求都要多写一次库。

相关接口：管理端 `GET/POST /admin/api/accounts/{id}/quota[/grant|/reset]`；用户端只读 `GET /admin/api/my/quota` 与 `GET /admin/api/my/quota/logs`。

## evkey 的申请与审批链路

### 用户侧：提交申请

普通用户在个人控制台「申请新的 API Key」处填写用途说明并提交。是否即时发放取决于配置：

- 管理员开启了「EVKey 申请需审批」（`EVKEY_APPROVAL_REQUIRED`，默认开启）且当前用户不是管理员：提交后进入**待审批**状态，提示「申请已提交，等待管理员审核」。
- 管理员本人，或关闭了审批：**直接生成**并弹窗显示完整 Key。

### 管理员侧：审批

进入「用户 → 申请」子标签。列表把**同一账号的多条申请折叠成一行**（列：账号、待审批数量、最近提交），点行首的展开箭头可**逐条**查看并「批准」/「拒绝」。勾选多行后可「批量批准」「批量拒绝」。导航上的红点显示的是**待审批的申请条数**。

- **单条「批准」/「拒绝」是静默的**：点完即生效，不弹窗、不提示、也不回显生成的 Key——Key 由申请人在个人控制台「我的 API Key」里自行查看，管理员不必转抄一遍。只有**失败**（超出持有上限、网络错误等）才会给出红色提示，否则会被误当成已批准。
- **批量批准 / 批量拒绝**只弹一次二次确认，且**只报数量**（「批准 N 个 evkey？」）；不再要求分配用户组，也不填备注。
- 批准时会**再卡一次该账号的 evkey 上限**（按申请单自带的用户组判定）：排队期间管理员可能已批准过同账号的其他申请，超限的那条会被跳过，并明确提示「有 N 个申请因超过持有上限未批准」，不会被当成已处理而静默消失。
- 审批中的申请**占用名额**：用户能同时持有的 evkey 上限按「已持有 + 审批中」计算。

## 设备端接入示例

设备用 **evkey** 鉴权，可放在请求头，也可放在查询参数。下例均为完整 URL（请把 `YOUR_EVKEY` 与主机端口替换成你自己的）。

### curl 拉取视图（默认 JPG）

```bash
curl -H "evkey: YOUR_EVKEY" \
  "http://127.0.0.1:5000/plugin_template/view/summary?size=hxl" \
  -o summary.jpg
```

视图路由的规则：

- 路径形如 `/{插件}/view/{视图种类}`。
- 视图**必须带 `size` 参数**（如 `hxl` / `h2xl`），否则返回「缺少 size 参数」。
- 输出格式用 `format` 参数指定（`jpg` / `png` / `bmp` / `webp` / `tiff` / `gif`，以及数组格式族 `array`、`bwarray`、`bwrarray`、`bwyarray`、`bwryarray`、`7carray`），不填用全局默认格式（`jpg`）；默认黑名单会拒绝 `png` / `bmp` / `webp` / `tiff` / `gif`，默认配置下只有 `jpg` / `jpeg` 与整个数组格式族可直接用。数组格式族返回的是按调色板索引打包的位流，取哪个由视图的调色板决定（`bwr` 用 `bwrarray`、`7color` 用 `7carray`），详见[数组格式族的解析](#esp8266--esp32-接入要点)。
- `rotate` 取 `c`（270°）/ `cc`（90°）/ `h`（180°），不填用默认旋转；`invert` 取 `t`（反色）/ `f`；`cmode` 取 `2bw` / `r2y` / `y2r` / `yr2r` / `yr2y` / `None`。**这些参数一律严格校验：取值不在上面的范围内会直接报 400（如「rotate 参数必须为 c / cc / h」），不会再静默按「不旋转 / 不映射」出图**，免得拼错参数却拿到一张正常的图。
- 其余查询参数原样透传给插件视图函数。

### curl 拉取 JSON

```bash
curl -H "evkey: YOUR_EVKEY" \
  "http://127.0.0.1:5000/plugin_template/json/demojson"
```

JSON 路由形如 `/{插件}/json/{名称}`，把所有查询参数透传给该模块的 `to_json()`。

也可以把 evkey 放在查询参数里：

```bash
curl "http://127.0.0.1:5000/plugin_template/view/detail?size=hxl&evkey=YOUR_EVKEY" \
  -o detail.jpg
```

### ESP8266 / ESP32 接入要点

以下是设备侧拉图的关键点伪代码（HTTP 客户端库因平台而异，这里只示意流程）：

```c
// 1) 建议优先用请求头传 evkey：URL 会进中间层与反向代理的访问日志，请求头不会
//    （本项目自己的请求日志已不记录 evkey）
const char* EVKEY = "YOUR_EVKEY";
// 2) 完整 URL：主机 + 视图路径 + 必需参数
const char* URL = "http://192.168.1.10:5000/plugin_template/view/summary?size=hxl";

http_begin(URL);
http_set_header("evkey", EVKEY);
http_set_timeout_ms(20000);        // 渲染可能较慢，超时不要设太短

int retry = 0;
uint8_t* buf; size_t len;
while (retry < 3) {                 // 3) 失败重试，指数退避（1s, 2s, 4s）
    int code = http_get(&buf, &len);
    if (code == 200) break;         // 4) 200 才是成图
    if (code == 401) break;         // 鉴权失败，重试无意义，检查 evkey
    if (code == 429) sleep_for_retry_after();   // 被限流：按 Retry-After 等待
    sleep_ms(1000 << retry);
    retry++;
}
// 5) 拿到的是整张图（默认格式，或你在 format 参数里指定的格式）
//    直接把字节刷到 e-paper 屏幕缓冲区；墨水屏整屏刷新慢，建议配合板载按键或定时唤醒
```

要点回顾：

- 穿透限流看：被限流时返回 429 与 `Retry-After`，等够时间再试，不要无脑快速重试。
- 拉图 URL 一定要带 `size`（视图）；格式用 `format` 指定。
- 为了降低服务端渲染压力，变化慢的视图建议改用[定时预渲染](#定时预渲染的使用)，让屏端直接命中成品图。

**数组格式族的解析**：`format=array` / `bwarray` / `bwrarray` / `bwyarray` / `bwryarray` / `7carray` 返回的是**按调色板索引打包的位流**（不是图片文件），码表为白=0、黑=1、红=2、黄=3、绿=4、蓝=5、橙=6，MSB 在前、每行末尾补 0 bit 到整字节，字节长度 = `ceil(宽×位数/8)×高`。选哪个格式由**视图用的调色板**决定（`bwr` 调色板的视图就用 `bwrarray`），降级/色彩映射仍由 `cmode` 控制。以 2bpp 为例：

```c
// 宽度 w、每像素 2 bit，行字节数 = (w*2 + 7) / 8
int row_bytes = (w * 2 + 7) / 8;
for (int y = 0; y < h; y++) {
    const uint8_t* row = buf + y * row_bytes;
    for (int x = 0; x < w; x++) {
        int bit = x * 2;
        int code = (row[bit >> 3] >> (6 - (bit & 7))) & 0x03;   // MSB 在前
        set_pixel(x, y, code);   // 0=白 1=黑 2=红 3=黄（bwrarray / bwyarray；bwryarray 还有 3=黄）
    }
}
```

## 定时预渲染的使用

定时预渲染把「变化慢」的视图/JSON 提前渲染成成品字节存进数据库，屏端请求只要**业务参数一致**就直接命中，延迟从「渲染耗时」降到「发文件」。仅 `run.py` 本地链路生效；Vercel 没有持久存储，整体降级为「没有预渲染」。

### 新建任务要填什么

在「定时」页点右上「新建任务」，弹窗说明：到点自动渲染一次并存入成品缓存；之后同路径、同业务参数的请求直接命中，旋转、反色、cmode 与输出格式由每个请求自己带，不再重新渲染。产物是**与格式无关的索引图**，所以同一个任务既服务 `format=jpg`，也服务 `format=bwrarray` / `7carray` 等数组格式族（各格式各自缓存编码结果）。表单字段：

- **任务名称**：留空则自动命名。
- **请求路径**：形如 `/插件/view/视图名` 或 `/插件/json/名称`。**插件名必须是路径第一段**，否则后端会拒。
- **查询参数**：与「测试」页同款，用 `&` 分隔。**视图任务必须在查询参数里带 `size`**（如 `size=hxl&city=beijing`），且对应的视图文件必须存在；JSON 任务无需 `size`。
- **缓存寿命（小时）**：填 `0` 或留空 = **不过期**，只由下次任务运行覆盖（项目约定 `0` 代表无限）。
- **排期方式**：`固定间隔`（间隔秒数，最小 10）、`每日时刻`（可填**多个** `HH:MM`，用空格 / 逗号 / 顿号分隔，按配置时区计算）或 `Cron 表达式`（5 段「分 时 日 月 周」，按配置时区计算。支持 `*`、`n`、`a-b`、`*/n`、`a-b/n` 与逗号列表，如 `*/15 * * * *` 每 15 分钟、`0 8 * * 1-5` 工作日 8:00；周字段 0 与 7 都表示周日，日与星期同时限定时按标准 cron 取「或」。**任一段非法整体判非法并报 400**，不会静默忽略）。
- **启用**：勾选后才会被调度。

保存时后端会校验路由真实存在、按与路由层同一份规则解析参数、算出缓存键；同插件、同路由、同参数的任务只能有一个，否则返回「同插件、同路由、同参数的任务已存在」。

### 任务列表与操作

任务列表只保留「任务 / 排期 / 命中 / 执行」四个关键值，点任务名（整格可点）打开**详情弹窗**看路由明细、查询参数、耗时、错误原因与成品信息。每行操作：

- **立即执行**：绕过排期立刻跑一次，跑完照常重排（不改计划）。
- **预览**：先用 `meta=1` 问清成品是 JSON 还是图片，图片直接在弹窗里直出。
- **编辑 / 停用（启用）/ 删除**。删除任务会连同该任务的成品缓存一起删掉。

页首还显示调度状态「调度 已启用/已停用 · 轮询 N 秒 · 执行中 N」；卡片指标为任务数、启用中、命中次数、命中率（`hits / (hits + runs)`，无数据显示 `-`）。

任务状态为 `失败` 或 `路由失效` 时会向配置的 **失败告警 Webhook**（配置页 → 定时）POST 一份 JSON，含任务名、插件、路由、状态、错误、耗时、发生时间与实例标识；留空即关闭告警。同一任务在 **告警最小间隔**（默认 600 秒，`0` = 每次都发）内只发一次，发送失败只打印堆栈，不影响调度。

### 成品缓存与寿命

「成品缓存」卡片显示缓存条数（`/ 上限 条`）、占用空间（`/ 上限 MB`）、平均单张、待回收条数，并提供「清空缓存」（任务保留，下个周期会重新生成）。

- **命中判定看「最后一次被请求」**，而不是「最后一次渲染」：周期重渲会一直刷新渲染时间，只看它的话没人读的条目永远回收不掉。因此判定用「最后命中时间，没命中过则退化为生成时间」。
- 过了任务寿命、且期间没被请求过的产物会被回收；条数/体积上限超出时按「最近使用」淘汰（LRU）。

### 什么不进缓存键

**`rotate` / `invert` / `cmode` / `format` 一律不进缓存键**。产物按索引数组存储，命中时按当次请求现场套用：`cmode` 是对调色板表的精确重映射，`rotate` / `invert` 是纯几何后处理。因此**同一次渲染能服务于任意格式**（除非该格式被用户组禁用或被全局黑名单关闭），不必为每种格式各缓存一份。

在面板上表现为：编辑任务时，查询参数框里**不会**回填这些后处理参数，详情弹窗里也只展示业务参数。

### 插件/路由被禁用时

命中不经过 Pillow，但仍会重跑格式与用户组权限校验。当插件或路由被禁用时，任务记为 `skipped`（已跳过）并**保留缓存**；只有插件目录被删才记为 `invalid`（路由失效）。

## 常见问题（FAQ）

**1. 为什么 Vercel 上没有管理面板？**
管理面板（`/admin`）、登录页、数据库、缓存、限流、请求日志、定时预渲染都只在 `run.py` 的本地链路里启用。Vercel 是纯 Serverless 部署，`create_app(mode='vercel')` 会停用数据库与缓存、跳过 lifecycle/后台线程/请求日志/限流/管理面板，鉴权走单 key（环境变量 `EVKEY`）。首页在 Vercel 上由静态文件边缘直出，不经 Python 函数。

**2. 我在面板改了配置，为什么没生效？**
面板改动（全局配置、插件配置、用户组限额、权限、插件/路由开关）都是**即时热更新**的：全局配置靠 `setattr` / 重载配置模块，插件配置靠清 `clear_plugin_config_cache()` 缓存（配置项与显示名一起失效），用户组限额与并发信号量在保存时显式失效。若确实没变，先确认保存成功（有成功提示）；另外框架自身 `modules/**` 的代码改动**仍需重启进程**，热重载只覆盖 `plugins/**`。

**3. 图片被限流了怎么办？**
请求被限流一般返回 429 并带 `Retry-After` 头，按提示等待再试。限流按账号计数：有用户组身份时用组里的「每分钟请求速率」，填 0 即真的不限；没有组身份（用环境变量 `EVKEY` 鉴权）时才回落到全局 `RATE_LIMIT_PER_MINUTE` / `RATE_LIMIT_PER_HOUR`。要治本可以在用户组里放宽速率，或让屏端降低刷新频率、改用定时预渲染命中成品图。

**4. 为什么同一账号的多个 key 共用额度？**
计数范围是**账号**而非单个 evkey：`rate_limit_per_minute`、`quota_limit` 都按账号独立计数，所以同一账号下所有 evkey 共享同一份速率与配额；不同账号互不影响。用户组只提供限额数值与权限。

**5. `0` 到底是不限还是禁止？**
绝大多数数值型上限 `0` 都表示**不限**：`rate_limit_per_minute`、`quota_limit`、`max_concurrent_renders`、定时缓存寿命、日志栈深度等。**唯一的例外是 `max_evkeys`**：它是三态，`-1` 不限、`0` **禁止创建**、`N` 最多 N 个。

**6. 预渲染任务建好了，请求却没命中，怎么排查？**
先确认「业务参数」完全一致：缓存键由插件名、路由路径、解析后的业务参数共同决定，`size` 是业务参数的一部分，必须和任务里填的一致。后处理参数（`rotate` / `invert` / `cmode` / `format`）**不进**缓存键，不一致也会命中，所以不命中通常不是它们的锅。再看：任务是否「启用」、是否已执行成功（详情弹窗里的执行结果是 `rendered` 还是 `error` / `skipped`）、插件与路由是否被禁用（禁用时任务跳过但保留缓存）、以及成品缓存是否被清空。改了任务参数后缓存键会变，旧键的产物会被顺手清掉，需要重新跑一次。

**7. 日志好像丢了？**
请求日志有双重上限：按「日志保留天数」按天清理，也按「日志栈深度」限制总条数（超出淘汰最旧）。写入是异步队列，队列满时溢出的条数会显示在日志页头部（`队列 size / maxsize（已丢弃 N 条）`）。如果监控在用 `/` 探活，会刷满日志表还可能被限流——请改用 `GET /healthz`（本地链路专用，不查库、不渲染、不写日志、不占额度）。

**8. 统计页的分位数据是不是偏低？**
p50/p95 与最慢路由榜都**排除了命中预渲染成品缓存的请求**——命中只需约 1 毫秒，混进来会把分位整体拉低。另外单个路由至少要 5 次渲染样本才会进入最慢路由榜。

**9. 缓存页的命中率是不是图片命中率？**
不是。缓存对象**只有字体文件**，命中/未命中反映的是字体加载；图片只做实时解码，不进池、不计命中。字体池不过期，重启后自动重建。

**10. 为什么删不掉某个用户组 / 某个账号的删除按钮是灰的？**
用户组三种情况：① **内置兜底组**（`id=1` admin、`id=2` Free）不可删除，按钮禁用并提示「内置用户组不可删除」，且它们的**类别与可访问分页也不可改写**；② 组下还有**「激活码开通且未到期」的账号**时不可删——那是用户花激活码换来的限期权限，提示会带上这类账号数（管理员手动提级或手动建号进来的账号不算，不阻止删除）；③ 删除落点是管理组时不允许（转进管理组等于批量授予后台权限）。删掉的组若正好是默认注册组，标记会随本次删除的落点转移，连带删除时落到内置兜底用户组。账号方面：管理组下的账号不参与批量操作，当前登录账号也不能被禁用或删除，**建库时生成的内置管理账号**（内置管理组里最早创建的那个，提示「内置管理账号不可删除」）连单独删除也会被拒绝——删掉它，后台就没有兜底的管理入口了。

**11. 发放额度时报「调整后总额度需至少为 1 次」是怎么回事？**
回收（填负数）不能把实际额度降到 0 或以下：0 在本项目等于「不限」、负数则永远放行不了，两者都会让配额静默走样，所以后端直接拒绝。另外用户组配额为 0（不限）时不允许发放，因为本来就不限。

**12. 设置了「按时间周期」的配额，到点会自动补发吗？**
不会。到期只把本周期已用归零，**未用部分不结转（额度不累加）**，每期固定就是配额值加已发放额。发放额本身跨周期保留。`trial`（按次总量）则永不自动重置，用完为止。
